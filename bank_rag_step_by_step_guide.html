평가 세트와 기준선을 먼저 세우고, 단계마다 한 가지만 바꿔 같은 세트로 다시 잽니다. 점수가 오른 것만 남기고, 그다음에 규모를 키웁니다. 이 문서는 함께 드린 노트북 bank_rag_step_by_step.ipynb의 셀을 순서대로 따라가며 코드, 코드 해석, 이론, 수행 가이드를 붙인 것입니다.

  • 노트북
    15단계, 코드 셀 54개. 모의 실행 기준 전체 실행에 20초 안팎
  • 예제 데이터
    가상의 은행 규정 29개 조항(폐지 2개 포함), 평가 문항 40개(시작용 16 + 2차 24)
  • 실행 방식

  • 이 문서의 숫자
    모의 실행 결과다. 검색 지표는 실제 계산값이지만, 답변 통과율은 모의 생성기의 값이라 실제 모델 성능이 아니다

0.이 자료를 쓰는 법

모든 단계는 같은 고리를 돕니다. 한 가지만 바꾸고, 같은 평가 세트로 재고, 나아졌을 때만 남긴다. 여러 가지를 한꺼번에 바꾸면 무엇이 효과를 냈는지 알 수 없고, 평가 세트가 바뀌면 숫자를 서로 비교할 수 없습니다.

실행 가이드

  1. 패키지 설치. Python 3.10 이상. 폐쇄망이면 외부망 PC에서 내려받아 반입한 뒤 설치합니다(아래 명령). Kiwi 모델 파일은 kiwipiepy 설치에 함께 들어옵니다. GPU 학습(11단계)에는 torch, sentence-transformers, datasets, trl, peft가 더 필요합니다.
  2. 실행. 노트북이 있는 폴더에서 jupyter lab을 열고 위에서부터 Shift+Enter로 한 셀씩 실행합니다. 셀이 data/, results/ 폴더를 만들고 파일을 씁니다.
  3. 점수판 확인. record()를 부르는 셀은 전체 점수판을 다시 보여 줍니다. 각 단계가 끝나면 새 줄이 기준선보다 나아졌는지 먼저 봅니다.
  4. 실제 모델로 바꾸기. 0-1 셀에서 USE_MOCK = False, 환경변수 LLM_BASE_URL(예: http://llm-gw.bank.local/v1), LLM_MODEL을 정하고 처음부터 다시 실행합니다. 8-2 셀의 사람 라벨은 그 모델의 답변을 읽고 새로 매겨야 합니다.
  5. 실데이터로 바꾸기. 0-3 셀을 건너뛰고 같은 필드(아래 0단계 표)를 가진 data/corpus.jsonl, data/eval_set.jsonl을 직접 둡니다. 나머지 셀은 그대로 씁니다.
  6. GPU가 필요한 셀. 11-3(임베딩 학습), 11-5(LoRA SFT)는 플래그가 False라 건너뜁니다. GPU 서버에서 True로 바꿔 실행합니다.

# 0-2. LLM 호출 함수 (USE_MOCK=False일 때만 쓰인다)
client = None
if not USE_MOCK:
    from openai import OpenAI
    client = OpenAI(base_url=LLM_BASE_URL, api_key=os.getenv("LLM_API_KEY", "EMPTY"))

def chat(prompt, system=None, max_tokens=400, temperature=0):
    messages = []
    if system:
        messages.append({"role": "system", "content": system})
    messages.append({"role": "user", "content": prompt})
    resp = client.chat.completions.create(model=LLM_MODEL, messages=messages,
                                          max_tokens=max_tokens, temperature=temperature)
    return resp.choices[0].message.content

코드 해석

  • vLLM, SGLang 같은 행내 서버는 OpenAI와 같은 형식의 API를 열어 주므로 openai 패키지를 그대로 씁니다. base_url만 행내 주소로 바꿉니다.
  • temperature=0: 같은 입력에 같은 답이 나오게 해 평가를 재현 가능하게 합니다.
  • 추론형 모델은 생각 과정이 섞여 나올 수 있습니다. vLLM에 추론 파서를 켜면 생각은 별도 필드로 빠지고 content에는 답만 남습니다.

이론: 검색 지표

Recall@k = |상위 k개 ∩ 정답| ÷ |정답|

  • 상위 k개: 검색기가 돌려준 앞쪽 k개 조항
  • 정답: 문항의 gold_ids

직관: 정답이 상위 k 안에 들어왔는가. 답변 모델이 근거 k개를 받는다면 R@k가 곧 "답할 재료가 들어왔는가"이다. 정답이 두 개인 복합 문항은 R@1이 최대 0.5다.

MRR = 평균( 1 ÷ 첫 정답의 순위 )

  • 첫 정답의 순위: 1위면 1, 2위면 0.5, 3위면 0.33, 없으면 0

직관: 정답을 얼마나 위에 올리는가. R@5가 같아도 MRR이 높으면 정답이 더 앞에 있다.

BM25(q, d) = Σt∈q IDF(t) · f(t,d)·(k₁+1) ÷ ( f(t,d) + k₁·(1 − b + b·|d|/avgdl) )

  • f(t,d): 문서 d에 단어 t가 나온 횟수
  • IDF(t): 드문 단어일수록 큰 가중치
  • |d|/avgdl: 문서 길이 ÷ 평균 길이, k₁, b: 조절값(rank_bm25 기본 1.5, 0.75)

직관: 질문의 드문 단어가 문서에 여러 번 나올수록 점수가 높고, 같은 횟수라면 짧은 문서가 유리하다. 단어가 글자 그대로 같아야 점수가 난다는 점이 3단계의 출발점이다.

# 2-1. 검색 지표
def recall_at_k(got_ids, gold_ids, k):
    """정답 조항 가운데 상위 k개 안에 들어온 비율"""
    return len(set(got_ids[:k]) & set(gold_ids)) / len(gold_ids)

def reciprocal_rank(got_ids, gold_ids):
    """첫 정답이 나온 순위의 역수: 1위면 1, 2위면 0.5, 없으면 0"""
    for rank, doc_id in enumerate(got_ids, start=1):
        if doc_id in gold_ids:
            return 1 / rank
    return 0.0

# 손으로 확인: 정답 B, D 중 상위 2개(A, B)에 B 하나 → 0.5 / 첫 정답 B가 2위 → 0.5
print(recall_at_k(["A", "B", "C"], ["B", "D"], k=2), reciprocal_rank(["A", "B", "C"], ["B", "D"]))

# 2-2. BM25 검색기
from rank_bm25 import BM25Okapi

def tokenize_space(text):
    return text.split()

def doc_text(doc, with_title=False):
    if with_title:
        return f"{doc['category']} > {doc['regulation']} > {doc['article']}\n{doc['text']}"
    return doc["text"]

def top_k(docs, scores, k, user_groups=None):
    """점수 높은 순으로 k개. user_groups가 있으면 권한 없는 문서는 건너뛴다(5단계에서 사용)."""
    results = []
    for i in np.argsort(-scores):
        if user_groups and not set(docs[i]["acl"]) & user_groups:
            continue
        results.append({**docs[i], "score": float(scores[i])})
        if len(results) == k:
            break
    return results

def make_bm25(docs, tokenize, with_title=False):
    """문서 목록으로 BM25 색인을 만들고, 그 색인으로 찾는 검색 함수를 돌려준다."""
    bm25 = BM25Okapi([tokenize(doc_text(d, with_title)) for d in docs])
    def search(query, k=5, user_groups=None):
        return top_k(docs, bm25.get_scores(tokenize(query)), k, user_groups)
    return search

# 2-3. 평가 함수와 점수판
def evaluate_retrieval(search, items, k=5, user_groups=None):
    rows = []
    for q in items:
        if not q["gold_ids"]:
            continue                      # 답변불가 문항은 검색 지표에서 뺀다(7단계에서 본다)
        got = search(q["question"], k=k, user_groups=user_groups)
        ids = [d["id"] for d in got]
        rows.append({"qid": q["qid"], "type": q["type"],
                     "R@1": recall_at_k(ids, q["gold_ids"], 1),
                     "R@5": recall_at_k(ids, q["gold_ids"], 5),
                     "MRR": reciprocal_rank(ids, q["gold_ids"]),
                     "폐지노출": any(d["status"] == "폐지" for d in got),
                     "top1": ids[0]})
    return pd.DataFrame(rows)

def changed(before, after, col="R@5"):
    """두 실행 결과에서 점수가 달라진 문항만 보여준다."""
    m = before[["qid", "type", col]].merge(after[["qid", col, "top1"]], on="qid", suffixes=("_전", "_후"))
    return m[m[f"{col}_전"] != m[f"{col}_후"]]

scoreboard = {}

def record(step, change, result=None, **extra):
    """점수판에 한 줄 기록하고 전체 점수판을 보여준다. 같은 단계를 다시 실행하면 덮어쓴다."""
    row = {"바꾼 것": change}
    if result is not None:
        row.update({"문항": len(result), "R@1": result["R@1"].mean(), "R@5": result["R@5"].mean(),
                    "MRR": result["MRR"].mean(), "폐지노출": result["폐지노출"].mean()})
    row.update(extra)
    scoreboard[step] = row
    return show(pd.DataFrame.from_dict(scoreboard, orient="index"))

def show(board):
    """화면용 표: 숫자는 소수 둘째 자리까지, 그 단계에서 재지 않은 칸은 "-"."""
    view = board.copy()
    for col in view.columns:
        if view[col].dtype == float:
            view[col] = [("-" if pd.isna(v) else f"{v:.2f}") for v in view[col]]
    return view

코드 해석

  • evaluate_retrieval(): 문항마다 검색하고 지표를 한 줄로 모아 표(DataFrame)로 돌려줍니다. 정답이 없는 답변불가 문항은 Recall의 분모가 0이 되므로 뺍니다. 그래서 점수판의 검색 문항 수는 16이 아니라 14입니다.
  • 폐지노출: 상위 5개에 폐지 조항이 하나라도 섞였는가. 5단계에서 0으로 만들 목표입니다.
  • changed(): 두 실행에서 점수가 달라진 문항만 보여 줍니다. 평균만 보면 한 문항이 좋아지고 다른 문항이 나빠진 것을 놓칩니다.
  • record(): 점수판 사전에 단계 이름을 열쇠로 한 줄을 넣습니다. 같은 셀을 다시 실행하면 같은 줄을 덮어써서 중복되지 않습니다. 그 단계에서 재지 않은 칸은 "-"로 보입니다.

def count_leaks(search, items, user_groups, apply_filter):
    """user_groups 사용자에게 보이면 안 되는 문서가 상위 5개에 몇 번 나왔나"""
    leaks = 0
    for q in items:
        got = search(q["question"], k=5, user_groups=user_groups if apply_filter else None)
        leaks += sum(1 for d in got if not set(d["acl"]) & user_groups)
    return leaks

6단계.의미 검색과 하이브리드

바꾸는 것
뜻이 비슷하면 찾는 검색기를 더하고, 두 결과를 순위로 합친다(RRF)
확인할 지표
R@5, MRR. 그리고 어떤 문항에서 서로 다른 답을 냈는가
넘어갈 기준
R@5가 오르거나, 같으면 MRR이 오를 때만 채택

이론

cos(q, d) = (q · d) ÷ (‖q‖ · ‖d‖)

  • q, d: 질문과 문서를 임베딩 모델로 바꾼 벡터
  • ‖·‖: 벡터의 길이

직관: 두 글의 뜻이 가까울수록 1에 가깝다. 벡터를 미리 길이 1로 맞춰 두면 내적(@) 한 번으로 계산된다.

RRF(d) = Σ검색기 s 1 ÷ (c + ranks(d)), c = 60

  • ranks(d): 검색기 s에서 문서 d의 순위
  • c: 상위 몇 개가 지나치게 앞서지 않게 하는 상수(Cormack 외 2009의 값)

직관: BM25 점수와 코사인 점수는 단위가 달라 더할 수 없다. 순위만 쓰면 단위 문제가 없고, 어느 한쪽에서라도 위에 있는 문서가 올라온다.

from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.preprocessing import normalize

def make_embedder(texts):
    if EMBED_MODEL_PATH:
        from sentence_transformers import SentenceTransformer
        model = SentenceTransformer(EMBED_MODEL_PATH)       # e5 계열은 "query: ", "passage: " 접두어가 필요
        def embed(xs):
            return model.encode(xs, normalize_embeddings=True)
        return embed
    vec = TfidfVectorizer(analyzer="char_wb", ngram_range=(2, 3)).fit(texts)   # 대체물: 글자 2~3개 조각
    def embed(xs):
        return normalize(vec.transform(xs)).toarray()
    return embed

def make_dense(docs):
    texts = [doc_text(d, with_title=True) for d in docs]
    embed = make_embedder(texts)
    doc_vecs = embed(texts)

        return top_k(docs, scores, k, user_groups)
    return search

# 6-2. 하이브리드: 두 결과를 순위로 합친다 (RRF, Reciprocal Rank Fusion)
def make_hybrid(search_a, search_b, depth=20, c=60):
    def search(query, k=5, user_groups=None):
        score, docs = {}, {}
        for s in (search_a, search_b):
            for rank, d in enumerate(s(query, k=depth, user_groups=user_groups), start=1):
                score[d["id"]] = score.get(d["id"], 0) + 1 / (c + rank)   # 두 쪽 모두 상위면 점수가 크다
                docs[d["id"]] = d
        best = sorted(score, key=score.get, reverse=True)[:k]           # 합친 점수 높은 순
        return [{**docs[i], "score": score[i]} for i in best]
    return search

# 7-2. 규칙 검사: 값싸고 결과가 늘 같으므로 LLM 채점보다 먼저 돌린다
STALE_IDS = {d["id"] for d in corpus if d["status"] == "폐지"}

def cited_ids(answer):
    return set(re.findall(r"\[([A-Z]{2}-[A-Z]{2}-\d{2}(?:-OLD)?)\]", answer))

def rule_check(q, answer):
    cited = cited_ids(answer)
    if q["type"] == "답변불가":
        return {"거부OK": ABSTAIN in answer and not cited}
    return {"사실OK": all(f in answer for f in q["must_include"]),   # 꼭 들어갈 말이 모두 있나
            "인용OK": bool(cited & set(q["gold_ids"])),             # 정답 조항을 인용했나
            "폐지없음": not (cited & STALE_IDS)}                     # 폐지 조항을 인용하지 않았나

def run_answers(search, items, user_groups=LOAN_STAFF, k=3):
    rows = []
    for q in items:
        docs = search(q["question"], k=k, user_groups=user_groups)
        answer = generate_answer(q["question"], docs)
        checks = rule_check(q, answer)
        rows.append({"qid": q["qid"], "type": q["type"], "critical": q["critical"], **checks,
                     "통과": all(checks.values()), "answer": answer, "docs": docs})
    return pd.DataFrame(rows)

8단계.LLM 채점기와 사람 라벨

바꾸는 것
규칙이 못 보는 "뜻이 맞는가"를 LLM 채점기로 보되, 먼저 사람 라벨과 맞춰 본다
확인할 지표
TPR, TNR, kappa. 특히 TNR(오답을 오답이라 하는 비율)
넘어갈 기준(예시)
TNR과 kappa가 정한 값 이상(예: kappa 0.6 이상)일 때만 채점기를 믿는다

왜 채점기를 검증하나

  • 규칙 검사는 "2만 5천원"과 "2만5천원"을 다르게 보고, 문장이 맞는 말인지 판단하지 못합니다. 그래서 LLM에게 채점을 맡깁니다.
  • 하지만 LLM 채점기도 틀립니다. 특히 그럴듯한 반쪽 답을 통과시키는 관대함이 흔합니다. 채점기가 틀리면 이후의 모든 비교가 틀리므로, 사람이 매긴 정답과 먼저 맞춰 봅니다.
  • 판정은 1~5점보다 PASS/FAIL 두 가지가 좋습니다. 사람과 맞추기 쉽고, 기준 문장을 고치는 효과도 바로 보입니다.

이론: 일치도 지표

TPR = TP ÷ (TP + FN), TNR = TN ÷ (TN + FP)

  • TP: 사람도 채점기도 정답, TN: 둘 다 오답
  • FP: 사람은 오답인데 채점기는 정답이라 함(위험), FN: 그 반대

직관: TNR이 낮으면 채점기가 오답을 통과시킨다. 운영에서 더 위험한 쪽은 이것이다.

κ = (po − pe) ÷ (1 − pe)

  • po: 실제로 일치한 비율
  • pe: 두 쪽이 각자의 비율대로 무작위로 판정했을 때 우연히 일치할 확률

직관: 정답이 대부분인 세트에서는 "전부 PASS"만 해도 일치율이 높다. 카파는 그 우연을 빼고 본다. 0이면 우연 수준, 1이면 완전 일치.

# 8-1. 채점 프롬프트 두 판: v1은 느슨한 기준, v2는 '핵심 사실이 모두 있어야' 통과
JUDGE_V1 = """질문과 모범답안을 보고 답변이 맞는지 판정하세요.
[질문] {question}
[모범답안] {reference}
[답변] {answer}
JSON 한 줄로만: {{"reason": "한 문장", "verdict": "PASS 또는 FAIL"}}"""

JUDGE_V2 = """질문과 모범답안을 보고 답변이 맞는지 판정하세요.
- 모범답안의 핵심 사실(숫자, 조건, 대상)이 모두 있어야 PASS입니다. 하나라도 빠지거나 틀리면 FAIL입니다.
- 표현 차이는 무시합니다. [근거]에 없는 내용을 지어냈으면 FAIL입니다.
[질문] {question}
[모범답안] {reference}
[근거] {context}
[답변] {answer}
JSON 한 줄로만: {{"reason": "한 문장", "verdict": "PASS 또는 FAIL"}}"""

def judge(q, answer, docs, version="v2"):
    if USE_MOCK:
        # 모의 채점기: v1은 꼭 들어갈 말이 '하나라도' 있으면, v2는 '모두' 있어야 PASS (느슨한 채점기를 흉내)
        hits = [f in answer for f in q["must_include"]]
        return any(hits) if version == "v1" else all(hits)
    template = JUDGE_V1 if version == "v1" else JUDGE_V2
    raw = chat(template.format(question=q["question"], reference=q["reference"],
                               context=format_context(docs), answer=answer), max_tokens=200)
    try:
        return json.loads(raw[raw.find("{"): raw.rfind("}") + 1])["verdict"] == "PASS"
    except (ValueError, KeyError):

def agreement(human, model):
    tp = sum(h and m for h, m in zip(human, model))               # 정답을 정답이라 함
    tn = sum((not h) and (not m) for h, m in zip(human, model))   # 오답을 오답이라 함
    fp = sum((not h) and m for h, m in zip(human, model))         # 오답을 정답이라 함 (위험)
    fn = sum(h and (not m) for h, m in zip(human, model))
    n = len(human)
    po = (tp + tn) / n                                            # 실제 일치율
    pe = ((tp + fp) * (tp + fn) + (fn + tn) * (fp + tn)) / n**2   # 우연히 맞을 확률
    return {"TPR": tp / max(tp + fn, 1), "TNR": tn / max(tn + fp, 1),
            "kappa": (po - pe) / (1 - pe) if pe < 1 else 1.0}

# 9-1. 짝지은 부트스트랩: 같은 문항을 복원추출해 '후보 - 기준' 통과율 차이의 분포를 만든다
def paired_bootstrap(base, cand, n_boot=10000, seed=0):
    rng = np.random.default_rng(seed)
    base = np.array(base, dtype=float)
    cand = np.array(cand, dtype=float)
    idx = rng.integers(0, len(base), size=(n_boot, len(base)))   # 한 줄 = 한 번의 재표본(문항 번호)
    diffs = (cand[idx] - base[idx]).mean(axis=1)
    return np.percentile(diffs, [2.5, 97.5])

def gate(base_df, cand_df, margin=0.02):
    m = base_df[["qid", "최종통과"]].merge(cand_df[["qid", "최종통과", "critical"]],
                                         on="qid", suffixes=("_기준", "_후보"))
    lo, hi = paired_bootstrap(m["최종통과_기준"], m["최종통과_후보"])
    broken = m[m["최종통과_기준"] & ~m["최종통과_후보"]]
    critical_broken = broken.loc[broken["critical"], "qid"].tolist()
    print(f"통과율 {m['최종통과_기준'].mean():.0%} → {m['최종통과_후보'].mean():.0%} | 차이 95% 구간 [{lo:+.0%}, {hi:+.0%}]")
    print("새로 깨진 문항:", broken["qid"].tolist(), "| 그중 핵심 문항:", critical_broken)
    print("후보에서 실패 중인 핵심 문항(원래 실패하던 것 포함):",
          m.loc[m["critical"] & ~m["최종통과_후보"], "qid"].tolist())
    ok = lo > -margin and not critical_broken        # 의미 있게 나빠지지 않았고, 핵심 문항이 안 깨졌을 것
    print("→ 배포 가능" if ok else "→ 배포 보류")
    return bool(ok)

코드 해석

  • rng.integers(0, n, size=(n_boot, n)): 1만 줄 × n칸의 문항 번호 표. 한 줄이 재표본 한 번입니다.
  • cand[idx] - base[idx]: 같은 번호끼리 짝지어 뺍니다. .mean(axis=1)로 줄마다 평균을 내면 차이 1만 개가 나옵니다.
  • np.percentile(diffs, [2.5, 97.5]): 아래 2.5%와 위 2.5% 지점. 이 사이가 95% 구간입니다.
  • gate(): 두 표를 문항 ID로 붙인 뒤 구간, 새로 깨진 문항, 핵심 문항을 출력하고 참/거짓을 돌려줍니다.

이론: 대조 학습 손실 (MNRL)

L = − log [ exp(s(q, p⁺)/τ) ÷ Σj exp(s(q, pj)/τ) ]

  • s(q, p): 질문과 조항 벡터의 코사인, p⁺: 정답 조항
  • pj: 정답과 같은 배치의 다른 조항들(오답으로 씀), τ: 온도(작을수록 차이를 크게 본다)

직관: 정답 조항과의 유사도는 올리고 배치 안 다른 조항과의 유사도는 내린다. 배치가 클수록 오답이 많아 학습 신호가 강해지고, 비슷하지만 틀린 조항(어려운 오답)을 넣으면 더 세밀하게 구분한다.

def make_pairs(docs, search, exclude, k=5):
    pairs = []
    for d in docs:
        for q in draft_questions(d):
            if q in exclude:
                continue                              # 평가 문항과 같은 질문은 학습에 쓰지 않는다

    return pairs

코드 해석 (GPU 서버에서 켰을 때)

  • mine_hard_negatives(..., range_min=2, range_max=30, num_negatives=1): 현재 모델로 질문마다 비슷한 조항을 찾아 어려운 오답 하나를 붙입니다. 최상위 2개는 건너뜁니다. 비슷한 조항이 사실 정답인 경우(거짓 오답)를 피하려는 것입니다.
  • InformationRetrievalEvaluator: 검증 쌍으로 검색 지표를 계산합니다. 학습 중 이 값이 가장 좋을 때의 모델을 남깁니다(load_best_model_at_end).
  • BatchSamplers.NO_DUPLICATES: 같은 배치에 같은 조항이 두 번 들어가면 정답이 오답 칸에도 들어가 학습을 망칩니다. 이를 막습니다.
  • warmup_steps=0.1: transformers 5.x에서는 warmup_ratio가 없어지고, warmup_steps에 0~1 사이 실수를 주면 전체 스텝 대비 비율로 해석합니다.
  • metric_for_best_model="eval_dev_cosine_ndcg@10": 평가기 이름(dev)과 유사도 함수(cosine)로 만들어지는 지표 이름입니다.

# 12-1. 등급 판정: 요청 등급 = 질문·첨부·검색 근거 가운데 가장 높은 등급
RANK = {"O": 0, "S": 1, "C": 2}                       # 공개 < 내부 < 기밀
PII = {   # 이름: (정규식, 등급). 한글 뒤 \b 경계가 안 먹으므로 앞뒤가 숫자가 아닌지로 경계를 잡는다
    "주민등록번호": (r"(?<!\d)\d{6}-?[1-4]\d{6}(?!\d)", "C"),   # 고유식별정보: 가명처리해도 외부 금지
    "휴대전화": (r"(?<!\d)01[016789]-?\d{3,4}-?\d{4}(?!\d)", "S"),
    "계좌번호": (r"(?<!\d)\d{3,6}-\d{2,6}-\d{2,8}(?!\d)", "C"),   # 금융거래정보
}
CONFIDENTIAL = ["신용등급", "연체내역", "고객번호", "인사평가"]

def find_pii(text):
    found = []
    for label, (pattern, grade) in PII.items():
        for m in re.finditer(pattern, text):
            value = m.group()
            if re.fullmatch(r"(19|20)\d{2}-\d{2}-\d{2}", value):
                continue                                    # 날짜(2026-07-01)를 계좌번호로 오인하지 않게
            if any(value in v or v in value for _, v, _ in found):
                continue                                    # 이미 잡힌 값과 겹치면 건너뛴다
            found.append((label, value, grade))
    return found

def max_grade(a, b):
    return a if RANK[a] >= RANK[b] else b

def classify(text, doc_grades=()):
    grade, reasons = "O", []
    for label, _, g in find_pii(text):
        grade = max_grade(grade, g); reasons.append(label)
    if any(w in text for w in CONFIDENTIAL):
        grade = "C"; reasons.append("기밀 용어")
    for g in doc_grades:
        grade = max_grade(grade, g); reasons.append(f"근거 등급 {g}")
    return grade, reasons or ["공개 정보"]

코드 해석

  • PII: 개인정보 종류마다 정규식과 등급을 둡니다. 주민등록번호·계좌번호는 C(가명처리해도 외부 금지), 휴대전화는 S(가명처리 후 외부 가능)로 둔 것은 예시이며, 실제 분류는 정보보호부 기준을 따릅니다.
  • (?<!\d), (?!\d): "앞뒤가 숫자가 아니다". 파이썬 정규식에서 한글은 단어 문자로 취급되어 "5432로" 같은 곳에서 \b 경계가 생기지 않으므로 이 방식으로 경계를 잡습니다.
  • 날짜(2026-07-01)는 계좌번호 패턴과 모양이 같아 따로 뺍니다. 휴대전화 번호는 계좌번호 패턴에도 맞으므로, 이미 잡힌 값과 겹치면 건너뜁니다.
  • classify(): 개인정보 등급, 기밀 용어, 근거 문서 등급 중 가장 높은 것을 요청 등급으로 정하고 이유를 함께 남깁니다.

# 12-2. 가명처리와 경로 결정. 외부 경로는 enabled에 있어야만 쓴다(기본 = 모두 꺼짐)
def pseudonymize(text):
    mapping = {}
    for i, (label, value, _) in enumerate(find_pii(text), start=1):
        token = f"<{label}{i}>"
        mapping[token] = value
        text = text.replace(value, token)
    return text, mapping                                    # mapping은 게이트웨이 밖으로 나가지 않는다

def restore(text, mapping):
    for token, value in mapping.items():
        text = text.replace(token, value)
    return text

def route(text, doc_grades=(), enabled=()):
    grade, reasons = classify(text, doc_grades)
    if grade == "O" and "external" in enabled:
        return {"등급": grade, "경로": "external", "보낸 글": text, "이유": reasons}
    if grade == "S" and "external-pseudo" in enabled:
        sent, _ = pseudonymize(text)
        if not find_pii(sent):                              # 가명처리 뒤에도 남아 있으면 외부로 보내지 않는다
            return {"등급": grade, "경로": "external-pseudo", "보낸 글": sent, "이유": reasons}
    return {"등급": grade, "경로": "internal", "보낸 글": text, "이유": reasons}   # 기본은 언제나 내부

13단계.DecisionRAG: 판단 모델이 목차를 따라 내려간다

바꾸는 것
색인 점수 대신 LLM이 "대분류 → 규정 → 조항"을 차례로 고르고, 기존 검색 상위 2개를 섞어 가지치기 실수를 되살린다
확인할 지표
R@1, R@5, 질문당 판단 호출 수(비용)
넘어갈 기준(예시)
채택 검색기보다 R@5나 MRR이 오르고, 늘어난 호출 비용과 지연을 감당할 수 있을 때만 채택

아이디어

  • 사람이 규정집을 찾을 때처럼 목차를 위에서부터 고릅니다. 각 층에서 후보 목록을 한 화면에 함께 보여 주고, 후보마다 "여기에 답이 있나?"를 yes/no 한 토큰으로 물어 yes의 확률을 점수로 씁니다.
  • 층마다 확률이 높은 몇 개만 남기는 빔 탐색이라, 한 번 버린 가지는 되살릴 수 없습니다. 그래서 기존 검색 결과를 섞는 안전망을 둡니다.

# 13-2. 판단 모델: 후보 목록을 함께 보여 주고, 후보마다 "여기에 답이 있나?"의 yes 확률을 받는다
CALLS = 0

def p_yes(question, cands, i):
    global CALLS
    CALLS += 1
    if USE_MOCK:   # 모의 판단: 질문과 후보 설명이 겹치는 낱말 수를 0~1로 바꾼다(구조 확인용)
        overlap = len(set(tokenize_ko(question)) & set(tokenize_ko(cands[i]["name"] + " " + cands[i]["desc"])))
        return 1 / (1 + math.exp(-(overlap - 1.5)))
    listing = "\n".join(f"[{j}] {c['name']}: {c['desc'][:300]}" for j, c in enumerate(cands))
    resp = client.chat.completions.create(
        model=LLM_MODEL, max_tokens=1, temperature=0, logprobs=True, top_logprobs=20,
        messages=[{"role": "system", "content": "yes 또는 no 한 단어로만 답하세요."},
                  {"role": "user", "content": f"후보 목록:\n{listing}\n\n질문: {question}\n후보 [{i}] 안에 이 질문의 답이 있습니까?"}],
        extra_body={"chat_template_kwargs": {"enable_thinking": False}})   # 추론형 모델은 생각 끄기
    probs = {"yes": 0.0, "no": 0.0}
    for t in resp.choices[0].logprobs.content[0].top_logprobs:
        word = t.token.strip().lower()
        if word in probs:
            probs[word] += math.exp(t.logprob)
    total = probs["yes"] + probs["no"]
    return probs["yes"] / total if total else 0.5             # 둘 다 상위에 없으면 '모름'

def navigate(question, root, beam=(2, 2, 3), user_groups=LOAN_STAFF):
    frontier = [root]
    for width in beam:                                        # 대분류 → 규정 → 조항, 세 번 고른다
        cands = []
        for node in frontier:
            for child in node["children"].values():
                if "doc" in child and not set(child["doc"]["acl"]) & user_groups:
                    continue                                  # 권한 없는 조항은 판단 모델에 보여 주지 않는다
                cands.append(child)
        scores = [p_yes(question, cands, i) for i in range(len(cands))]
        order = np.argsort(scores)[::-1][:width]              # yes 확률 높은 순으로 width개만 남긴다
        frontier = [cands[i] for i in order]
        last_scores = [scores[i] for i in order]
    return [{**node["doc"], "score": s} for node, s in zip(frontier, last_scores)]

A부

1. 정답 조항이 {A, C}이고 검색 결과가 [B, A, D, E, F]일 때 R@1, R@5, MRR은?

R@1 = 0(1위 B는 오답), R@5 = |{A}| ÷ 2 = 0.5, MRR = 1 ÷ 2 = 0.5(첫 정답 A가 2위).

2. 답변불가 문항을 검색 지표 계산에서 빼는 이유는?

정답 조항이 없어 Recall의 분모가 0이 되기 때문입니다. 이 문항은 7단계에서 "거부OK"로 따로 봅니다.

3. 시나리오: 팀원이 점수를 올리려고 평가 문항 몇 개를 프롬프트 예시로 넣자고 한다. 어떻게 답하나?

넣으면 그 문항의 점수는 오르지만 실제 성능을 재는 능력을 잃습니다(누수). 예시가 필요하면 평가 세트와 겹치지 않는 별도 문항으로 만듭니다.

B부

1. 공백 토큰으로 "연차휴가는 며칠 받나요?"가 "…15일의 연차휴가를 준다."를 못 찾은 이유는?

"연차휴가는"과 "연차휴가를"이 조사 때문에 서로 다른 토큰이 되어 하나도 겹치지 않았기 때문입니다. 형태소 분석은 둘 다 "연차", "휴가"로 남깁니다.

2. RRF(c = 60): 문서 X는 BM25 1위·의미 검색 3위, 문서 Y는 BM25 2위·의미 검색 1위. 어느 쪽이 위인가?

X = 1/61 + 1/63 = 0.01639 + 0.01587 = 0.03227, Y = 1/62 + 1/61 = 0.01613 + 0.01639 = 0.03252. Y가 조금 위입니다. 두 검색기에서 고르게 상위인 문서가 올라옵니다.

3. 시나리오: "권한 필터 대신 프롬프트에 '권한 없는 문서는 답하지 마'를 넣으면 되지 않나?"

안 됩니다. 문서가 모델 입력에 들어간 순간 요약, 우회 질문, 프롬프트 주입으로 흘러나갈 수 있습니다. 권한은 검색 단계에서 문서를 아예 넣지 않는 방식으로 통제합니다.

C부

1. 사람 라벨 대비 채점기가 TP 10, TN 3, FP 1, FN 0일 때 카파는?

n = 14, po = 13/14 = 0.929, pe = (11×10 + 3×4)/196 = 0.622, κ = (0.929 − 0.622)/(1 − 0.622) ≈ 0.81. 8-2 셀 v1의 값과 같습니다.

2. 통과율이 올랐는데 게이트가 "배포 보류"를 내는 경우는?

새로 깨진 문항 중에 핵심 문항이 있을 때입니다. 평균이 올라도 금리·한도·보안 같은 문항 하나가 틀리면 사용자 신뢰가 무너집니다.

3. 시나리오: 16문항에서 통과율이 70% → 75%가 되었다. 배포해도 되나?

이 차이로는 판단할 수 없습니다. 16문항이면 통과율 하나의 95% 구간 반폭이 ±20%p 수준이라 5%p 차이는 우연과 구별되지 않습니다. 문항을 늘리거나, 적어도 핵심 문항이 깨지지 않았는지와 구간 하한이 허용 범위 안인지를 봅니다.

D부

1. 임베딩 학습 쌍을 문항 단위가 아니라 규정 단위로 학습/검증에 나누는 이유는?

같은 규정의 질문은 서로 비슷합니다. 학습과 검증에 섞이면 모델이 일반화하지 않아도 검증 점수가 높게 나와(누수) 교체 판단을 그르칩니다.

2. "고객 계좌 110-234-567890 관련 보고서 문장 다듬어줘", 근거 등급 S. 3단계(가명처리 외부 허용)에서 어디로 가나?

계좌번호가 C등급이므로 요청 등급은 C, 경로는 내부 모델입니다. 외부 경로가 켜져 있어도 C등급에는 외부 경로가 없습니다.

3. 판단 모델의 yes 로그확률이 −0.2, no가 −1.8이면 P(yes)는?

e−0.2 = 0.819, e−1.8 = 0.165, P(yes) = 0.819 ÷ (0.819 + 0.165) ≈ 0.83.

4. 시나리오: 외부 모델 사용이 승인되었는데, 가명처리 뒤에도 주민등록번호 패턴이 남는 요청이 들어왔다.

외부로 보내지 않고 내부 모델로 처리합니다(닫힌 쪽으로 실패). 그 요청은 감사 로그에 이유와 함께 남기고, 가명처리기가 놓친 패턴을 판정기 평가 세트에 추가합니다.

핵심 요약

  1. 평가 세트와 기준선을 먼저 만들고, 한 번에 하나만 바꿔 같은 세트로 잰다. 세트가 바뀌면 기준선도 다시 잰다.
  2. 검색은 형태소 → 제목 → 현행·권한 필터 → 하이브리드처럼 값싼 것부터, 답변은 규칙 검사 → 사람 라벨로 검증한 채점기 → 게이트 순서로 본다.
  3. 파인튜닝, 외부 모델, DecisionRAG는 지표가 필요하다고 말할 때 꺼내고, 게이트를 통과할 때만 채택한다.
