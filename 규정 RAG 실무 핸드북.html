제 1 장

왜 단순 RAG는 깨지는가

가장 기본적인 형태의 RAG가 실무에서 무너지는 다섯 지점을 먼저 짚습니다. 이 다섯 가지가 나머지 열두 개 장의 목차가 됩니다.

1.1우리가 지금까지 한 것

보통 처음 RAG를 배울 때 만드는 구조는 이렇습니다. 이것을 Naive RAG라고 부릅니다.

1.2다섯 개의 고장 지점

고장구체적 증상해결 위치
의미 절단 500자에서 잘려 "다만, 다음의 경우는 제외한다"가 다음 청크로 넘어감. 단서 조항이 사라진 채 답변됨 구조 인식 청킹 (3장)
문맥 소실 청크에 "이 경우 전항의 한도를 준용한다"만 남음. 전항이 무엇인지 알 수 없어 검색도 이해도 불가 위치 정보 주입 · 부모 청크 (3장, 8장)
최신성 개정 전·후 조문이 동시에 top-k에 들어옴. 문장이 90% 같아 벡터 공간에서 분리 불가 메타데이터 필터 (4장, 7장)
어휘 불일치 "제15조", "LTV 70%", "BIS비율" 같은 고유명사·숫자를 벡터가 놓침 BM25 하이브리드 (6장)
고정 top-k 관련 문서가 0개인데 억지로 4개를 채워 넣어 LLM이 엮어서 답함 리랭커 + 임계값 (8장)
가장 먼저 버려야 할 직감 검색 결과가 나쁠 때 임베딩 모델을 더 큰 것으로 바꾸고 싶어집니다. 대부분의 경우 원인은 그 앞 단계, 즉 청킹과 메타데이터에 있습니다. 파싱에서 누락되거나 잘못 라벨링된 조항은 어떤 모델을 써도 찾을 수 없습니다. 이 핸드북의 3.3절에 실제 사례가 있습니다.

1.3이 문서가 목표로 하는 구조

앞으로 만들 파이프라인은 이렇게 길어집니다. 지금 전부 이해할 필요는 없고, 각 장을 읽은 뒤 이 그림으로 돌아와서 자기 위치를 확인하면 됩니다.

제 2 장

RAG 기초 다지기

이미 아는 내용이면 3장으로 건너뛰어도 됩니다. 다만 "왜 파인튜닝이 아니라 RAG인가"와 "청크·임베딩·유사도"의 정확한 의미는 뒤에서 계속 쓰이므로 한 번 정리하고 갑니다.

2.1RAG가 하는 일

LLM은 학습 시점 이후의 정보나 사내 문서를 모릅니다. 모르는 걸 물으면 그럴듯하게 지어냅니다. RAG(Retrieval-Augmented Generation)는 이 문제를 아주 단순하게 해결합니다. 답하기 전에 관련 문서를 찾아서 프롬프트에 붙여준다는 것입니다.

비유하자면 시험을 오픈북으로 바꾸는 것입니다. 학생(LLM)의 머리를 다시 만드는 게 아니라, 문제를 풀 때 필요한 페이지를 찾아서 책상 위에 펼쳐 놓아 줍니다. 그래서 RAG의 성능은 LLM이 얼마나 똑똑한가보다 올바른 페이지를 펼쳐 줬는가에 훨씬 크게 좌우됩니다. 이 핸드북의 거의 전부가 "올바른 페이지를 펼치는 법"인 이유입니다.

2.2핵심 용어 네 가지

청크(chunk)

문서를 검색 가능한 단위로 자른 조각입니다. 너무 크면 관련 없는 내용이 섞여 검색 정밀도가 떨어지고, 너무 작으면 문맥이 끊겨 이해가 안 됩니다. 규정 문서에서는 "제15조 제2항" 같은 법적 단위가 자연스러운 청크 크기입니다. 3장에서 자세히 다룹니다.

임베딩(embedding)

텍스트를 숫자 배열(벡터)로 바꾸는 것입니다. 예를 들어 bge-m3는 문장 하나를 1024개의 숫자로 바꿉니다. 핵심은 의미가 비슷한 문장은 비슷한 숫자 배열이 된다는 것입니다. 그래서 "대출 한도가 얼마야"와 "여신 최대 금액은"이 서로 가까운 위치에 놓입니다.

코사인 유사도(cosine similarity)

두 벡터가 이루는 각도로 유사성을 재는 방법입니다. 값은 −1에서 1 사이이고, 1에 가까울수록 비슷합니다. 벡터 길이(크기)를 무시하고 방향만 보기 때문에, 문장 길이가 달라도 공정하게 비교됩니다.

벡터 데이터베이스

수만~수억 개의 벡터 중에서 질의 벡터와 가까운 것을 빠르게 찾아 주는 저장소입니다. 전부 하나씩 비교하면 느리기 때문에 HNSW 같은 근사 최근접 탐색(ANN) 알고리즘을 씁니다. "근사"이므로 아주 드물게 진짜 1등을 놓칠 수 있지만, 속도 이득이 압도적이라 표준으로 쓰입니다. 이 실습에서는 설치가 간단한 Chroma를 씁니다.

벡터DB는 필수가 아닙니다 청크가 수천 개 수준이면 numpy 배열에 전부 넣고 내적 한 번 계산하는 게 더 빠르고 단순합니다. 벡터DB를 쓰는 진짜 이유는 속도보다 메타데이터 필터링, 영속화, 증분 업데이트입니다. 이 핸드북에서 Chroma를 쓰는 이유도 where 필터 때문입니다.

제 3 장

파싱과 청킹 — 여기서 진 승부는 뒤집히지 않는다

검색 품질의 절반 이상이 이 단계에서 결정됩니다. 파싱에서 놓치거나 잘못 라벨링한 조항은 어떤 임베딩 모델, 어떤 리랭커를 써도 복구되지 않습니다.

3.1고정 분할이 실패하는 이유

규정 문서는 자연스러운 줄글이 아니라 구조화된 트리입니다. 장 → 절 → 조 → 항 → 호로 내려가고, 각 노드가 독립된 법적 의미를 가집니다. 이걸 문자 수로 자르는 건 JSON 파일을 500바이트씩 자르는 것과 같습니다.

3.2청킹 전략 비교

전략방식장점한계
고정 길이 N자마다 자름, 보통 overlap 10~20% 구현 3줄, 어떤 문서에도 적용 의미 절단. 출처 특정 불가
재귀 분할 문단 → 문장 → 단어 순으로 구분자를 낮춰가며 자름 (LangChain 기본) 고정보다 훨씬 자연스러움 조항 번호를 모름. 표를 망침
구조 인식 문서 문법(제N조, 제N장)을 정규식으로 파싱 정확한 인용, 계층 메타데이터 확보 문서 유형마다 파서를 만들어야 함
시맨틱 인접 문장 임베딩 유사도가 급락하는 지점에서 자름 구조가 없는 줄글에 효과적 비용 높음. 규정에는 과잉

규정·약관·매뉴얼처럼 번호 체계가 있는 문서는 무조건 구조 인식입니다. "문서 유형마다 파서를 만들어야 한다"는 단점은 실제로는 큰 부담이 아닙니다. 사내 문서는 대개 서너 가지 양식으로 수렴하고, 한 번 만든 파서는 계속 재사용됩니다.

법령체 파서

매뉴얼체 파서

디딤돌 업무처리기준은 제N장 아래 1 대출한도 같은 섹션이 오는 구조입니다.

parser_manual.py제N장 → N 섹션
P_CHAPTER = re.compile(r"^제\s*(\d+)장\s+(\S.*)$")
P_SECTION = re.compile(r"^(\d{1,2})\s+([가-힣A-Za-z(].{1,35})$")

def looks_like_section(line):
    # '5 우대금리'는 섹션 제목, '3인 이상인 가구'는 본문.
    # 짧고, 서술어로 끝나지 않고, 불릿이 없어야 섹션으로 본다.
    m = P_SECTION.match(line)
    if not m:
        return None
    title = m.group(2).strip()
    if title.endswith(("다", "다.", "함", "음", ")")) or "▪" in line:
        return None
    return f"{m.group(1)}. {title}"

def parse_manual(pages, header, skip_pages=3):
    chunks, chapter, cur = [], "", None
    for pno, text in pages:
        if pno <= skip_pages:              # 표지 · 목차 건너뛰기
            continue
        for line in clean_lines(text, header):
            m = P_CHAPTER.match(line)
            if m:
                chapter = f"제{m.group(1)}장 {m.group(2).strip()}"
                cur = None; continue
            sec = looks_like_section(line)
            if sec:
                cur = {"article": chapter or "(장 미상)", "title": sec,
                       "clause": "", "text": "", "page": pno}
                chunks.append(cur); continue
            if cur:
                cur["text"] += " " + line
    return [c for c in chunks if len(c["text"].strip()) > 20]

NOISE = [
    re.compile(r"^-\s*\d+\s*-$"),     # "- 12 -"
    re.compile(r"^\d{1,3}$"),          # 단독 페이지 번호
    re.compile(r"·{5,}"),               # 목차 점선
]

def norm(s):
    return re.sub(r"\s+", "", s)          # ★ 공백 무시 비교용

def clean_lines(text, header):
    out = []
    for raw in text.split("\n"):
        line = re.sub(r"-\s*\d+\s*-\s*$", "", raw).strip()
        if not line or norm(line) == norm(header):   # ★
            continue
        if any(p.search(line) for p in NOISE):
            continue
        out.append(line)
    return out
공백 하나 때문에 머리말이 안 지워진다 실습에서 PDF 머리말은 금융기관 여신운용 세칙(공백 포함)인데 설정의 문서명은 금융기관 여신운용세칙(공백 없음)이었습니다. 단순 == 비교가 실패해 머리말이 모든 페이지에서 살아남았고, 일부 청크 본문 한가운데에 끼어들었습니다. norm()으로 공백을 없애고 비교하면 해결됩니다.

4.1왜 벡터로는 안 되는가

개정 전 조문과 개정 후 조문은 문장이 90% 이상 같습니다. 바뀐 것은 숫자 하나, 단서 하나뿐입니다. 임베딩 모델은 이 둘을 거의 같은 위치에 놓습니다. 그게 모델이 제대로 작동한 결과입니다. 의미가 비슷하니까 비슷하다고 한 것이죠. 어느 쪽이 지금 유효한지는 문서 내용이 아니라 문서 바깥의 사실이므로, 텍스트를 아무리 잘 이해해도 알 수 없습니다.

6.2BM25가 점수를 매기는 방식

BM25는 세 가지를 봅니다. 수식을 외울 필요는 없고 직관만 알면 됩니다.

  1. TF (단어 빈도) — 문서에 그 단어가 많이 나올수록 점수가 올라갑니다. 다만 포화가 있어서, 10번 나온 게 5번 나온 것의 두 배 점수가 되지는 않습니다.
  2. IDF (역문서 빈도) — 전체 문서 중 그 단어를 가진 문서가 적을수록 점수가 큽니다. "금융기관"처럼 모든 청크에 있는 단어는 변별력이 없어 점수가 낮고, "유산스"처럼 한 청크에만 있는 단어는 점수가 매우 큽니다.
  3. 문서 길이 정규화 — 긴 문서는 단어가 많아 유리하므로 길이로 나눠 보정합니다.

6.3한국어 토크나이징

BM25는 단어 단위로 동작하는데, 한국어는 조사가 붙어서 "대출보증은"과 "대출보증을"이 다른 단어로 취급됩니다. 형태소 분석기를 쓰는 것이 정석입니다.

def tokenize(text):
    # 한글 2자 이상 / 영문 2자 이상 / 숫자(%포함)만 추출
    toks = re.findall(r"[가-힣]{2,}|[A-Za-z]{2,}|\d+(?:\.\d+)?%?", text)
    out = []
    for t in toks:
        out.append(t)
        if re.match(r"^[가-힣]{3,}$", t):
            out.append(t[:2])      # 조사 제거 대용: 앞 2글자도 함께 넣음
    return out

6.4RRF — 두 결과를 합치는 법

벡터 유사도는 0~1, BM25 점수는 0~30 같은 식으로 스케일이 완전히 다릅니다. 그냥 더하면 BM25가 지배하고, 정규화해서 더하면 분포에 따라 결과가 불안정합니다. 그래서 점수를 버리고 순위만 가지고 합치는 RRF(Reciprocal Rank Fusion)를 씁니다.

rrf.py구현은 다섯 줄이면 끝
def rrf(rank_lists, k=60, weights=None):
    weights = weights or [1.0] * len(rank_lists)
    score = {}
    for w, ids in zip(weights, rank_lists):
        for rank, _id in enumerate(ids, 1):
            score[_id] = score.get(_id, 0) + w * 1 / (k + rank)
    return sorted(score, key=score.get, reverse=True)

# 규정 도메인이면 BM25 가중치를 조금 높여도 좋다
fused = rrf([dense_ids, bm25_ids], weights=[1.0, 1.2])
k 값의 의미 k=60은 원 논문의 경험값입니다. k가 작으면 1위와 2위의 점수 차가 커져 한쪽 검색기의 1위가 결과를 지배합니다. k가 크면 순위 간 차이가 평탄해져 양쪽에 고루 등장하는 문서가 유리해집니다. 검색기 하나를 신뢰한다면 k를 낮추고, 둘 다 비슷하게 믿는다면 60 이상을 쓰세요.

def search(query, top_k=4, pool=20, verbose=True):
    mode, asof = route(query)              # 7장
    where = build_where(mode, asof)

        # (a) 필터를 먼저 걸어 후보를 좁힌다
    #     검색 후에 거르면 top-k 자리를 폐지 문서가 차지해 버린다
    cand = COLL.get(where=where)
    if not cand["ids"]:
        return []

    # (b) 벡터 검색
    qv = EMB.encode([query], normalize_embeddings=True).tolist()
    dense_ids = COLL.query(query_embeddings=qv,
                           n_results=min(pool, len(cand["ids"])),
                           where=where)["ids"][0]

    # (c) BM25 — 필터 통과분만 대상으로
    bm25 = get_bm25(f"{mode}:{asof}", cand["documents"])
    sc = bm25.get_scores(tokenize(query))
    order = sorted(range(len(sc)), key=lambda i: -sc[i])[:pool]
    bm25_ids = [cand["ids"][i] for i in order]

    # (d) 융합
    fused = rrf([dense_ids, bm25_ids])[:top_k]
    look = {i: (d, m) for i, d, m in
            zip(cand["ids"], cand["documents"], cand["metadatas"])}
    return [{"id": i, "text": look[i][0], "meta": look[i][1]} for i in fused]
필터 순서가 성능과 정확도를 동시에 좌우합니다 (a)에서 COLL.get(where=...)로 후보를 미리 확보하는 이유는 두 가지입니다. 첫째, BM25를 필터 통과분만 대상으로 만들어 폐지 문서가 키워드로 끌려오는 걸 막습니다. 둘째, 검색 후 후처리로 거르면 top-k가 이미 폐지 문서로 채워진 뒤라 남는 게 없습니다.

def route(q):
    # ① 이력·변경을 묻는 질문 → 전 버전 대상
    if re.search(r"(옛날|과거|예전|이력|바뀌|변경|개정|폐지|연혁)", q):
        return "all", None

    # ② 연도가 등장하면 그 시점 기준 → as-of
    m = re.search(r"(19|20)\d{2}\s*년", q)
    if m:
        year = int(re.sub(r"\D", "", m.group()))
        mo = re.search(r"년\s*(\d{1,2})\s*월", q)
        day = re.search(r"월\s*(\d{1,2})\s*일", q)
        return "asof", (year * 10000
                        + (int(mo.group(1)) if mo else 1) * 100
                        + (int(day.group(1)) if day else 1))

    # ③ 기본값 — 현행만
    return "current", None


def build_where(mode, asof):

    if mode == "asof":

                         {"effective_to":   {"$gte": asof}}]}
    return None      # mode == "all"

검색을 "빠르게 대충 많이"와 "느리지만 정확하게 조금" 두 단계로 나눕니다. 그리고 LLM에게는 검색한 것보다 넓은 범위를 건넵니다.

8.1Bi-encoder와 Cross-encoder

지금까지 쓴 임베딩 모델은 bi-encoder입니다. 질의와 문서를 따로 벡터로 만든 뒤 비교합니다. 문서 벡터를 미리 계산해 둘 수 있어 빠르지만, 질의와 문서가 서로를 "보지" 못합니다.

cross-encoder는 질의와 문서를 붙여서 한 번에 모델에 넣습니다. 단어 수준으로 교차 비교가 일어나 훨씬 정확하지만, 미리 계산해 둘 수 없어 매 질의마다 문서 수만큼 모델을 돌려야 합니다.

8.3부모 청크 확장 (Small-to-Big)

검색은 작고 정밀한 단위(항)로 하고, LLM에게 넘길 때는 큰 단위(조 전체)로 확장합니다. 항 단위로만 넘기면 단서 조항이 통째로 빠집니다.

# 인덱싱 시 조 전체 텍스트를 별도 저장해 둔다 (벡터는 만들지 않아도 됨)
PARENT_STORE = {}      # {"BOK-CREDIT-1991#art05": "제5조 전문 …"}

def expand_to_parent(hits):
    seen, out = set(), []
    for h in hits:
        pid = h["meta"].get("parent_id")
        if pid and pid not in seen:
            seen.add(pid)
            out.append({**h, "text": PARENT_STORE[pid]})   # 본문만 교체
        elif not pid:
            out.append(h)
    return out

def build_context(hits):
    blocks = []
    for i, h in enumerate(hits, 1):
        m = h["meta"]
        blocks.append(
            f"<근거 {i}>\n"
            f"문서: {m['doc_title']} ({m['issuer']}) / 상태: {m['status']}\n"

from transformers import AutoTokenizer, AutoModelForCausalLM
import torch

MODEL = "Qwen/Qwen3-4B-Instruct-2507"
tok = AutoTokenizer.from_pretrained(MODEL)
mdl = AutoModelForCausalLM.from_pretrained(MODEL, torch_dtype="auto", device_map="auto")

def llm(system, user):
    msgs = [{"role": "system", "content": system},
            {"role": "user",   "content": user}]

        # ① 템플릿 적용은 '텍스트'만 뽑는다 (tokenize=False)
    prompt = tok.apply_chat_template(msgs, tokenize=False, add_generation_prompt=True)

    # ② 인코딩은 tok()으로 따로
    inputs = tok(prompt, return_tensors="pt").to(mdl.device)

    with torch.no_grad():
        out = mdl.generate(**inputs, max_new_tokens=400, do_sample=False)

    # ③ 입력 길이만큼 잘라서 디코딩
    return tok.decode(out[0][inputs["input_ids"].shape[-1]:], skip_special_tokens=True)
apply_chat_template의 반환형 함정 최신 transformers에서 apply_chat_template(..., return_tensors="pt")는 텐서가 아니라 BatchEncoding(딕셔너리형)을 반환합니다. 이걸 텐서로 알고 ids.shape이나 generate(ids, ...)를 호출하면 아래 오류가 납니다.
KeyError: 'shape' → AttributeError File transformers/generation/utils.py, in generate batch_size = inputs_tensor.shape[0]

위 코드처럼 tokenize=False로 문자열만 뽑고 tok()으로 따로 인코딩한 뒤 generate(**inputs)로 언팩하면 해결됩니다.

Recall@k 상위 k건 안에 들어온 정답 청크 비율 가장 먼저 봐야 할 지표. 여기가 낮으면 뒤는 의미 없음
Precision@k 상위 k건 중 정답인 비율 노이즈가 얼마나 섞였는지. 리랭커 효과를 볼 때 유용
MRR 첫 정답이 r번째면 1/r, 평균 1.0이면 항상 1위. 0.5면 평균 2위. 정답이 앞에 오는지 봄
nDCG@k 순위에 로그 할인을 적용한 누적 이득 정답이 여러 개이고 중요도가 다를 때 사용

     "gold": ["BOK-CREDIT-1991#008"], "mode": "asof"},
        # ★ '답이 없어야 정상'인 질문도 반드시 넣는다
    {"q": "대출보증은 총대출금의 몇 % 이내인가요?", "gold": []},
    # … 최소 20문항까지 채우세요
]

def evaluate(k=4):
    rec, prec, mrr, abstain_ok = [], [], [], []
    for r in GOLDEN:
        got = [h["id"] for h in search(r["q"], top_k=k, verbose=False)]
        gold = set(r["gold"])

        if not gold:                          # 정답이 없어야 하는 질문
            abstain_ok.append(1.0 if not got else 0.0)
            continue

        hit = set(got) & gold
        rec.append(len(hit) / len(gold))
        prec.append(len(hit) / max(len(got), 1))
        mrr.append(next((1/(i+1) for i, g in enumerate(got) if g in gold), 0))

    avg = lambda xs: sum(xs)/len(xs) if xs else 0
    print(f"Recall@{k}    = {avg(rec):.3f}")
    print(f"Precision@{k} = {avg(prec):.3f}")
    print(f"MRR          = {avg(mrr):.3f}")
    print(f"올바른 기권율  = {avg(abstain_ok):.3f}")
1문항 Recall 1.00은 측정이 아니라 우연입니다 실습에서 골든셋 1문항으로 Recall@4 = 1.00이 나왔습니다. 이 상태에서는 3장의 부칙 버그를 고쳐도 숫자가 1.00 → 1.00으로 그대로라 "개선 효과 없음"으로 오독하게 됩니다. 최소 20문항, 가능하면 현업 질문 50문항을 채우세요.

10.3골든셋 만드는 법

  1. 현업 질문을 모읍니다. 상상해서 쓰지 말고 실제 창구 문의, 사내 메신저 질문, 기존 FAQ에서 가져오세요. 표현의 거칠음까지 그대로 살리는 게 중요합니다.
  2. 정답 청크 id를 사람이 지정합니다. 3장의 청크 목록 출력을 옆에 띄워 놓고 찾습니다. 정답이 여러 개면 모두 적습니다.
  3. 답이 없어야 하는 질문을 20% 정도 섞습니다. 다른 규정 소관, 폐지된 내용, 아예 무관한 질문. 이게 없으면 임계값을 정할 수 없습니다.
  4. 시점 질문을 넣습니다. as-of 모드가 깨지는 걸 잡아내려면 골든셋에 연도가 들어간 질문이 있어야 합니다.
  5. 변경할 때마다 돌립니다. 청킹 규칙, 토크나이저, top-k, 임계값 — 뭘 건드리든 이 함수를 먼저 돌리고 숫자를 기록하세요.

# ── 노이즈 제거 ──────────────────────────────────────────
NOISE = [re.compile(r"^-\s*\d+\s*-$"), re.compile(r"^\d{1,3}$"), re.compile(r"·{5,}")]
norm = lambda s: re.sub(r"\s+", "", s)

def read_pages(path):
    with pdfplumber.open(path) as pdf:
        return [(p.page_number, p.extract_text() or "") for p in pdf.pages]

def clean_lines(text, header):
    out = []
    for raw in text.split("\n"):
        line = re.sub(r"-\s*\d+\s*-\s*$", "", raw).strip()
        if not line or norm(line) == norm(header):
            continue
        if any(p.search(line) for p in NOISE):
            continue
        out.append(line)
    return out

# ── 법령체 파서 ──────────────────────────────────────────
P_ARTICLE = re.compile(r"^제\s*(\d+)조(?:의\s*(\d+))?\s*\(([^)]+)\)\s*(.*)$")
P_CLAUSE  = re.compile(r"^([①-⑳])\s*(.*)$")
P_ADDENDA = re.compile(r"^부\s*칙\s*<")
CIRCLED   = "①②③④⑤⑥⑦⑧⑨⑩⑪⑫⑬⑭⑮"

def parse_law(pages, header):
    chunks, cur = [], None
    for pno, text in pages:
        for line in clean_lines(text, header):
            if P_ADDENDA.match(line):
                d = re.search(r"(\d{4})\.\s*(\d{1,2})\.\s*(\d{1,2})", line)
                label = f"부칙<{d.group(1)}.{d.group(2)}.{d.group(3)}>" if d else "부칙"
                cur = {"article": label, "title": "부칙", "clause": "",
                       "text": "", "page": pno, "addenda": True}
                chunks.append(cur); continue
            m = P_ARTICLE.match(line)
            if m:
                no = f"제{m.group(1)}조" + (f"의{m.group(2)}" if m.group(2) else "")
                cur = {"article": no, "title": m.group(3), "clause": "제1항",
                       "text": m.group(4), "page": pno, "addenda": False}
                chunks.append(cur); continue
            m = P_CLAUSE.match(line)
            if m and cur:
                idx = CIRCLED.index(m.group(1)) + 1
                cur = {**cur, "clause": f"제{idx}항", "text": m.group(2), "page": pno}
                chunks.append(cur); continue
            if cur:
                cur["text"] += " " + line
    return [c for c in chunks if c["text"].strip()]

# ── 매뉴얼체 파서 ────────────────────────────────────────
P_CHAPTER = re.compile(r"^제\s*(\d+)장\s+(\S.*)$")
P_SECTION = re.compile(r"^(\d{1,2})\s+([가-힣A-Za-z(].{1,35})$")

def looks_like_section(line):
    m = P_SECTION.match(line)
    if not m: return None
    t = m.group(2).strip()
    if t.endswith(("다", "다.", "함", "음", ")")) or "▪" in line: return None
    return f"{m.group(1)}. {t}"

def parse_manual(pages, header, skip_pages=3):
    chunks, chapter, cur = [], "", None
    for pno, text in pages:
        if pno <= skip_pages: continue
        for line in clean_lines(text, header):
            m = P_CHAPTER.match(line)
            if m:
                chapter = f"제{m.group(1)}장 {m.group(2).strip()}"; cur = None; continue
            sec = looks_like_section(line)
            if sec:
                cur = {"article": chapter or "(장 미상)", "title": sec, "clause": "",
                       "text": "", "page": pno, "addenda": False}
                chunks.append(cur); continue
            if cur: cur["text"] += " " + line
    return [c for c in chunks if len(c["text"].strip()) > 20]

# ── 청크 조립 ────────────────────────────────────────────
def build(doc):
    pages = read_pages(f"{PDF_DIR}/{doc['file']}")
    raw = (parse_law if doc["style"] == "law" else parse_manual)(pages, doc["title"])
    out = []
    for i, c in enumerate(raw):
        loc = " > ".join(x for x in (c["article"], c["title"], c["clause"]) if x)
        out.append({
            "id": f"{doc['doc_id']}#{i:03d}",
            "text": f"[{doc['title']} / {loc}]\n{c['text'].strip()}",
            "meta": {"doc_id": doc["doc_id"], "doc_title": doc["title"],
                     "issuer": doc["issuer"], "location": loc, "page": c["page"],
                     "is_addenda": c["addenda"],
                     "effective_from": doc["effective_from"],
                     "effective_to": doc["effective_to"],
                     "is_current": doc["is_current"], "status": doc["status"]},
        })
    return out

CHUNKS = [c for d in DOCS for c in build(d)]

    m = re.search(r"(19|20)\d{2}\s*년", q)
    if m:
        y = int(re.sub(r"\D", "", m.group()))
        mo = re.search(r"년\s*(\d{1,2})\s*월", q)
        return "asof", y*10000 + (int(mo.group(1)) if mo else 1)*100 + 1
    return "current", None

def build_where(mode, asof):
    if mode == "current": return {"is_current": True}
    if mode == "asof":
        return {"$and": [{"effective_from": {"$lte": asof}},
                         {"effective_to": {"$gte": asof}}]}
    return None

def tokenize(text):
    toks = re.findall(r"[가-힣]{2,}|[A-Za-z]{2,}|\d+(?:\.\d+)?%?", text)
    out = []
    for t in toks:
        out.append(t)
        if re.match(r"^[가-힣]{3,}$", t): out.append(t[:2])
    return out

def rrf(lists, k=60):
    sc = {}
    for ids in lists:
        for r, i in enumerate(ids, 1): sc[i] = sc.get(i, 0) + 1/(k+r)
    return sorted(sc, key=sc.get, reverse=True)

def search(query, top_k=4, pool=20, threshold=0.3, verbose=True):
    mode, asof = route(query)
    where = build_where(mode, asof)

    key = f"{mode}:{asof}"
    if key not in _cache:
        cand = COLL.get(where=where)
        _cache[key] = (cand, BM25Okapi([tokenize(d) for d in cand["documents"]]))
    cand, bm25 = _cache[key]
    if not cand["ids"]: return []

    qv = EMB.encode([query], normalize_embeddings=True).tolist()
    dense_ids = COLL.query(query_embeddings=qv,
                           n_results=min(pool, len(cand["ids"])),
                           where=where)["ids"][0]

    sc = bm25.get_scores(tokenize(query))
    bm25_ids = [cand["ids"][i]
                for i in sorted(range(len(sc)), key=lambda i: -sc[i])[:pool]]

    look = {i: (d, m) for i, d, m in
            zip(cand["ids"], cand["documents"], cand["metadatas"])}
    hits = [{"id": i, "text": look[i][0], "meta": look[i][1]}
            for i in rrf([dense_ids, bm25_ids])[:pool]]

    # 리랭킹 + 임계값
    scores = RERANKER.predict([(query, h["text"]) for h in hits])
    ranked = sorted(zip(hits, scores), key=lambda x: -x[1])
    final = [h for h, s in ranked[:top_k] if s >= threshold]

    if verbose:
        print(f"[mode={mode}] 후보 {len(cand['ids'])} → 융합 {len(hits)} → 최종 {len(final)}")
        for h, s in ranked[:top_k]:
            mark = "✓" if s >= threshold else "✗"
            print(f"  {mark} {s:.3f} [{h['meta']['status']}] {h['meta']['location'][:50]}")
    return final
