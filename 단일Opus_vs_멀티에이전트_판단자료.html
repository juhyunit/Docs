0한눈에 보기: 세 질문에 대한 답

세 질문에 대한 짧은 답

  1. 왜 단일 Opus가 더 좋았나? 같은 모델끼리 구조만 겨룬 시험이 아니었습니다. 실행 권한·원자료·라이브러리·시간·사전지식을 모두 가진 강한 연구자 한 명과, 이것들이 막힌 보수적인 위원회가 겨뤘습니다. 격차 대부분은 단일이냐 멀티냐보다 이 조건 차이에서 나왔습니다(1부, 3부).
  2. 역할·지침을 고치면 나아지나? 문구만 고치면 효과가 작습니다. 지표 정합, 실행 샌드박스, 넓게 보고 좁히는 탐색, 잡음에 맞춘 채택 규칙, 맥락을 하나로 쥔 리드처럼 구조를 바꾸면 상당 부분 좁힐 수 있습니다. 연구들도 같은 방향입니다(5부).
  3. 오픈 모델 조합이 Opus 단독보다 잘할까? "오픈 모델 여러 개를 섞은 멀티에이전트"가 Opus 단독을 넘는다는 근거는 지금 약합니다. "가장 강한 오픈 모델 하나 + 잘 만든 탐색 하네스 + 넉넉한 시도 예산"은 상당히 따라붙습니다. 실제로 비교해야 할 것은 도구 단독이 아니라 데이터사이언티스트 + 도구입니다(6부).

실무 권고 세 줄

  1. 가설 → 실험 → 해석으로 이어지는 핵심 추론 루프는 가장 강한 모델 하나가 전체 맥락을 쥐고 직접 코드를 돌리게 합니다. 멀티에이전트는 병렬 실험 가지와 독립 검토에만 씁니다.
  2. 판정 지표 = 공식 지표, 리크 정책, CV–LB 차이 추적을 하네스의 첫 기능으로 만듭니다. 이 셋이 모델 성능보다 먼저 결과를 좌우합니다.
  3. 오픈 모델은 "여럿 조합"이 아니라 "가장 강한 오픈 모델 하나 + 좋은 하네스 + 사람"으로 시작합니다. 결정 전에 비공개 데이터 3개 이상으로 2×2 비교(7.2절)를 합니다.

"근본 모델은 같다"는 전제부터

실제로 무엇과 무엇이 비교됐는지

1.1비교된 것은 두 아키텍처가 아니라 두 시스템이다

두 실행은 Claude라는 점만 같습니다. 결과를 좌우하는 조건은 대부분 달랐습니다.

그래서 이 결과로 "단일이 멀티보다 낫다"를 결론 내릴 수 없습니다. 말할 수 있는 것은 "이 조건 묶음이 이 결과를 냈다"까지입니다. 구조의 효과만 보려면 같은 모델·같은 환경에서 구조만 바꿔 비교해야 합니다(7.2절).

1.2agent-lab이 모든 면에서 못한 것은 아니다

  • 숫자의 신뢰도는 agent-lab이 높습니다. Opus는 조기 종료 시점을 검증 fold로 정해 CV가 다소 낙관적이라고 스스로 적었습니다. 최종 스크립트도 축소 데이터로만 끝까지 돌려 봤습니다.
  • agent-lab은 홀드아웃 확인(보험 AUC +0.0031로 CV 개선과 일치), 재현 검증(원본과 예측 상관 1.0000), 교란 점검, 미해결 비판 기록까지 남겼습니다.
  • 운영 환경에서는 이 장점이 점수 0.01보다 중요할 때가 많습니다. 버릴 것은 검증 규율이 아니라, 검증 규율이 탐색까지 막는 설계입니다.

2.1보험 청구: 격차의 85%는 출발선에서 생겼다

Gini = 2 × AUC − 1

AUC: 양성을 음성보다 높게 줄 세우는 확률. 직관: 둘 다 순위만 보므로 같은 정보이고, Gini 차이는 AUC 차이의 2배입니다. 이하 모두 Gini로 환산했습니다.

출발점 차이의 정체는 무엇인가?

  • agent-lab 기준 모델: HistGradientBoosting 기본값(학습률 0.1, 200회, 규제 없음). _cat 컬럼도 정수로 학습.
  • Opus 기준 모델: LightGBM에 열 샘플링 0.4, 리프 최소 200개, L1·L2 규제. 이 대회에서 잘 알려진 설정에 가깝습니다. Opus는 XGBoost 설정을 공개 커널에서 가져왔다고 밝혔습니다.
  • 즉 출발점 차이 = 라이브러리 선택(환경 문제) + 이 대회에 맞는 설정을 이미 앎(사전지식 문제). 3부 ①과 ⑦에 해당합니다.

과정의 차이: 작은 진짜 개선을 쌓았나?

  • 같은 아이디어를 둘 다 시험했습니다. ps_calc 제거는 agent-lab에서도 첫 시드 +0.00177(AUC)로 Opus보다 컸습니다. 그러나 다른 시드에서 +0.00033으로 줄어 기각됐습니다. 최종 모델의 중요도 상위 15개에 ps_calc_10·ps_calc_11이 남았습니다.
  • 비판가는 원인을 정확히 짚었습니다. 판정 잡음은 조기 종료의 내부 10% 분할과 bin 샘플링에서 온다는 진단입니다. 팀장은 "한 번에 하나" 원칙 때문에 평가 방식 변경을 미뤘고, 그대로 연속 3회 미채택이 되어 25분 만에 실행이 끝났습니다. 시스템의 원칙이 시스템의 문제 해결을 막은 장면입니다.

손계산: 채택 규칙은 진짜 개선을 얼마나 버리나?

  1. 잡음 크기 추정(로그 기반): 같은 후보가 시드만 바꿔 +0.00177 → +0.00033, +0.00120 → +0.00049로 움직였습니다. fold별 잡음 표준편차 0.0008, 시드를 바꿀 때 전체가 함께 움직이는 잡음 0.0007(AUC)로 두었습니다.
  2. 규칙 재현: 평균 ≥ 0.00107, 4/5 fold 개선, t ≥ 1. 평균이 0.00214 미만이면 다른 시드에서 ≥ 0.00053을 다시 요구합니다.
  3. 모의실험: 실제 개선 δ마다 4만 회 반복해 채택 확률을 셌습니다.
1종 오류 = 효과 없는데 채택 · 2종 오류 = 효과 있는데 기각

직관: 현재 규칙은 1종 오류를 2%대로 거의 막는 대신, +0.0009짜리 진짜 개선을 10번 중 7번 버립니다. 이 대회처럼 순위가 0.00x 차이로 갈리는 문제에서는 2종 오류의 비용이 큽니다.

참고과적합이 걱정되면 무엇을 봐야 하나? Roelofs 등(NeurIPS 2019)은 캐글 대회 100여 개를 분석해 공개 순위를 반복해서 봐도 실질적인 과적합 증거는 적다고 보고했습니다. 반복 평가를 지나치게 경계하기보다 분포 이동과 2종 오류를 더 경계하는 편이 손실이 작을 때가 많습니다. 마지막 안전장치는 잠근 홀드아웃입니다.

2.2고객 가치: 점수 차이의 대부분은 '리크'와 '잘못된 과녁'

Opus가 한 일

  • 4,459행 × 4,993열, 값의 96.9%가 0. 지표가 RMSLE라 log1p(target)의 RMSE 문제로 정의했습니다.
  • 대회 당시 공개된 "40개 컬럼 = 시간 순서 거래 금액" 구조를 떠올리고 train으로 검증했습니다(k−2 위치 1,275건 중 1,275건 일치).
  • 같은 구조를 가진 다른 컬럼 묶음을 데이터에서 자동으로 찾았습니다(길이 40 사슬 71개). 기억한 묶음이 그 안에서 독립적으로 재현됐습니다.
  • 정답 복원 비율 74.5% → 86.8%, train 결합 RMSLE 약 0.70 → 0.50, 모의 test 0.661 → 0.475.
  • 스스로 밝힌 한계: 점수 대부분이 데이터 결함에서 나오고, 모델만의 성능은 약 1.34입니다.

agent-lab이 한 일

  • 하네스 지표 목록에 RMSLE가 없어 rmse를 골랐고, 타깃 변환 없이 원 단위 RMSE로 판정했습니다.
  • 첫 루프에서 분석가가 "판정 지표가 brief(RMSLE)와 다르다. 팀장이 결정하거나 사용자에게 확인해야 한다"고 적었습니다. 실행 중 사용자에게 묻는 경로가 없었습니다.
  • 그 결과 log1p 학습(R1-L2)은 원 단위 RMSE가 365,183 나빠져 기각됐습니다. 이후 10루프 전부가 원 단위 RMSE로 판정됐습니다. log 타깃 모델을 블렌드에 섞은 R1-L9도 같은 기준으로 기각됐습니다.
  • 최종 모델: HGB 4시드 + ExtraTrees, 원 단위 타깃. CV RMSE 6,516,104, 홀드아웃 R² 0.387.
  • 원자료 행을 보지 못하고 fit_predict(X_train, X_valid) 틀 안에서만 고칠 수 있어, 행 사이의 시간 이동 구조를 찾을 수도 쓸 수도 없었습니다. 학습·테스트 구분 AUC 0.937이라는 강한 신호도 원인 분석 없이 "남은 위험"으로 끝났습니다.

손계산: 원 단위로 맞추면 log 척도에서 얼마나 틀리나?

log 오차 = | ln(1 + ŷ) − ln(1 + y) |

ŷ: 예측, y: 실제. 직관: RMSLE는 "몇 배 틀렸나"를 봅니다. 원 단위 제곱오차를 줄이는 모델은 조건부 평균 쪽으로 예측하는데, 치우친 금액에서는 평균이 중앙값보다 훨씬 큽니다(이 데이터: 중앙 2.26M, 평균 5.94M).

  1. 예측이 평균 5.94M일 때, 실제 100,000원이면 log 오차 4.08.
  2. 실제 2.26M(중앙값)이면 0.97.
  3. 실제 40M(최댓값)이면 1.91.
  4. 해석: 작은 고객이 많은 데이터에서는 이런 큰 log 오차가 RMSLE를 지배합니다. 검산: ln(5,940,001/100,001) = 4.08.

모의 실험: 같은 모델, 다른 과녁 (합성 데이터)

  • 원 단위 RMSE로 판정하면 log 학습이 "나빠 보입니다". agent-lab R1-L2와 같은 방향입니다.
  • RMSLE로 판정하면 log 학습이 0.75 앞섭니다.
  • 핵심은 방향입니다. 과녁이 틀리면 엄격한 판정 규칙이 틀린 방향을 정확하게 밀어 줍니다.
python · 합성 데이터로 과녁 불일치 재현 (핵심 부분)
# 합성 데이터(사용자 데이터 아님): 오른쪽으로 치우친 금액 타깃, 약한 신호
import numpy as np
from sklearn.ensemble import HistGradientBoostingRegressor
from sklearn.model_selection import KFold

rng = np.random.default_rng(0)
X = rng.normal(size=(4500, 30))
logy = 14.5 + 0.6*X[:, 0] + 0.4*X[:, 1] - 0.3*X[:, 2]*X[:, 3] + rng.normal(scale=1.3, size=4500)
y = np.clip(np.expm1(logy), 3e4, 4e7)          # 중앙값 약 1.9M, 평균 약 5.2M, 최대 4e7

rmse  = lambda a, b: np.sqrt(np.mean((a - b) ** 2))
rmsle = lambda a, b: rmse(np.log1p(a), np.log1p(np.clip(b, 0, None)))

for tr, va in KFold(5, shuffle=True, random_state=1).split(X):
    m_raw = HistGradientBoostingRegressor(max_iter=300, learning_rate=0.05).fit(X[tr], y[tr])
    m_log = HistGradientBoostingRegressor(max_iter=300, learning_rate=0.05).fit(X[tr], np.log1p(y[tr]))
    p_raw, p_log = m_raw.predict(X[va]), np.expm1(m_log.predict(X[va]))
    # fold별 rmse(y[va], p), rmsle(y[va], p)를 모아 평균한다
주의리크를 어떻게 볼 것인가?
  • 대회에서는 리크 활용이 상위권의 필수 조건이었습니다. 한 참가자 기록에서 리크 미사용 최고 Private 1.373(2,206위)이 리크 사용 후 0.530(28위, 금메달)이 됐습니다.
  • 실무에서는 같은 결함이 있으면 오히려 사고입니다. 다만 "행 사이 구조(중복, 시간 이동, ID 연결)를 찾아내는 능력"은 실무의 누수 탐지에 그대로 쓰입니다.
  • agent-lab의 설계(원본 행 미전달, fold 단위 계약, 만점 감지 시 중단)는 운영 관점에서 타당합니다. 그래서 이 대회 LB로 두 방식을 비교하는 것 자체가 공정하지 않습니다.

2.3고장 진단 대회(사용자 제공 4자 비교)도 같은 패턴

  • 세 참가 방식 모두 트리 기본값 0.79 근처에서 출발했습니다.
  • Opus는 "고장 신호가 변수 사이의 관계에 있다"로 문제를 다시 정의했습니다(LightGBM → QDA, +0.087). 예측 개수의 이상에서 분포 이동을 찾아 보정했습니다(LB 약 0.83 → 0.8995).
  • agent-lab은 10루프로 +0.019를 얻었습니다. 적대적 검증 AUC 0.742와 LDA 효과를 기록했지만 트리 계열 안에서 움직였습니다.
  • 그 자료도 "모델 차이·LB 피드백·시점·1회 실행"이 섞여 있어 구조 자체의 우열 증거로 쓰기 어렵다고 결론 냈습니다. 이 문서의 결론과 같습니다.

2.4세 사례의 공통점: 큰 이득은 모두 '문제 재정의'에서 나왔다

큰 이득은 "같은 모델을 더 잘 다듬기"가 아니라 "문제를 다시 정의하기"에서 나왔습니다. 문제 재정의에는 ① 원자료를 보는 눈 ② 바로 돌려 보는 손 ③ 끊기지 않는 추론 사슬 ④ 배경 지식이 필요합니다. agent-lab은 넷 다 막혀 있었습니다.

3부

왜 이런 차이가 생기나: 원인 8가지

이번 기록의 증거와 연구 근거를 짝지어

①환경·권한: 손발이 묶이면 모델이 좋아도 소용없다

  • 이번 증거: 셸 금지로 실행 불가, scikit-learn만 사용, 180초 제한, 원본 행 미전달.
  • 연구: MLE-bench 원 논문에서 같은 GPT-4o의 메달률이 스캐폴드에 따라 8.7%(AIDE), 4.4%(OpenHands), 0.8%(MLAB)로 갈렸습니다. AIRA-dojo는 같은 o1-preview·같은 AIDE를 더 안정적인 실행 환경으로 옮기기만 해도 MLE-bench Lite 메달률이 35.2% → 45.9%가 됐다고 보고했습니다.
  • 시사점: 모델·구조를 비교하기 전에 실행·데이터·라이브러리부터 맞춰야 공정한 비교가 됩니다.

②탐색·채택 방식: 좁게, 보수적으로만 움직였다

  • 이번 증거: 보험 8루프 중 채택 1건, 25분 만에 종료. 검정력 모의실험(2.1절)에서 +0.0009 개선의 채택 확률 30%.
  • 연구: AIRA-dojo는 에이전트를 "탐색 정책 × 연산자(초안·디버그·개선 같은 코드 수정 단위)"로 보고, 둘의 조합이 성능을 좌우하며 연산자가 병목이라고 밝혔습니다. 연산자만 바꿔도 39.8% → 45.5%였습니다. MLE-STAR는 웹 검색으로 좋은 출발 모델을 고르고, 절제 실험(ablation)으로 영향이 큰 코드 블록을 찾아 그 부분만 깊게 개선해 MLE-bench Lite 64%를 냈습니다.
  • 시사점: "한 번에 하나"는 원인 분리에는 좋지만 탐색 초반에는 너무 좁습니다. 넓게 본 뒤 좁히는 2단계가 표준입니다.

③명세 오류: 과녁이 틀리면 모든 루프가 헛돈다

  • 이번 증거: 가치 예측의 판정 지표 불일치. 분석가의 확인 요청이 갈 곳이 없었습니다.
  • 연구: MAST는 멀티에이전트 실패를 명세(시스템 설계) 문제, 에이전트 간 불일치, 검증 실패의 세 갈래로 나눴습니다. 세부 실패 양식에 "명확화를 묻지 않음"이 있습니다.
  • 시사점: 가장 싸고 효과가 큰 수정입니다. 킥오프에서 공식 지표로 기준 모델 점수를 계산해 보여 주는 것을 의무로 합니다.

④정보 손실: 요약의 요약은 원본보다 많이 알 수 없다

  • 이번 증거: 분석가(Opus)가 후보를 내면 팀장(Sonnet)이 하나를 고르고, 엔지니어는 계획 문장만, 검증자는 diff만 받습니다. 비판가의 정확한 진단(시드 잡음)은 원칙에 막혀 보류됐습니다.
  • 연구: Cognition은 전체 궤적을 공유하고, 행동에는 암묵적 결정이 담긴다는 점을 기억하라고 했습니다. Tran & Kiela(2026)는 같은 추론 토큰 예산이면 단일 에이전트가 정보 효율이 더 높다는 정보이론 논증을 냈습니다. MAST에도 "정보 보류", "다른 에이전트 입력 무시"가 있습니다.
X → Y → Z 이면 I(X; Z) ≤ I(X; Y)

데이터 처리 부등식. X: 원자료, Y: 분석가 요약, Z: 팀장 계획, I: 상호정보량. 직관: 전달 단계를 거칠 때마다 원자료에 대한 정보는 늘지 않고 줄 수만 있습니다. 넘길 때는 요약보다 수치표·원 기록을 넘겨야 합니다.

⑤핵심 결정자의 능력: 무엇을 할지 정하는 자리가 가장 중요하다

  • 이번 증거: 실험을 정하는 팀장과 코드를 쓰는 엔지니어가 Sonnet. Opus는 조언 자리에 있었습니다.
  • 연구: Google 등의 180개 구성 통제 실험에서 단일 에이전트 기준 성능이 약 45%를 넘으면 협업 이득이 줄거나 음수가 됐고, 순차 추론 과제에서는 모든 멀티에이전트 변형이 39~70% 하락했습니다. 독립 병렬 에이전트는 오류를 17.2배 증폭했고, 중앙 조정은 4.4배로 막았습니다. Gao 등(2025)도 LLM이 강해질수록 멀티에이전트의 이점이 줄어든다고 보고했습니다.
  • 시사점: 데이터 분석 루프는 대부분 순차적이고 앞 결과가 다음 질문을 만듭니다. 가장 강한 모델을 리드 자리에 두는 것이 먼저입니다.

⑥비판의 방향: 위생은 지켰지만 패러다임은 묻지 않았다

  • 이번 증거: 비판가는 시드 잡음·누수·교란 해석 같은 통계 위생에 집중했습니다. "이 모델 계열의 가정이 데이터와 맞나", "학습·테스트 AUC 0.937의 원인은 무엇인가" 같은 질문은 나오지 않았습니다.
  • 연구: Huang 등(ICLR 2024)은 외부 피드백 없는 자기 수정이 추론 성능을 오히려 떨어뜨릴 수 있고, 멀티에이전트 토론의 이득은 같은 응답 수의 다수결과 비슷하다고 보고했습니다. agent-lab이 비판을 실제 확인 실험으로 판정한 것은 연구가 권하는 방향(외부 피드백)입니다.
  • 시사점: 비판의 형식은 좋습니다. 질문 목록을 "위생"에서 "패러다임"으로 넓히면 됩니다.

⑦사전지식·오염: 공개 대회는 기억을 쓰는 쪽에 유리한 시험지다

  • 이번 증거: Opus는 ps_calc 노이즈, ps_reg_03 정수 복원, XGBoost 공개 설정, 리크 40개 컬럼 목록을 기억에서 꺼냈다고 직접 밝혔습니다. 각각 데이터로 검증한 점은 좋은 습관입니다.
  • 연구: MLE-bench는 GPT-4o의 대회 친숙도와 성적 사이에 양의 상관을 찾지 못했지만, 미묘한 오염 효과까지 배제할 수는 없다고 밝혔습니다.
  • 시사점: 사내의 새 데이터에서는 이 이점이 줄어듭니다. 도입 판단용 비교는 비공개·신규 데이터로 해야 합니다.

⑧연산·시간 예산: 일찍 멈추면 쌓을 기회도 없다

  • 이번 증거: agent-lab 보험 25분. Opus는 CatBoost 5 fold에만 50~80분을 썼습니다.
  • 연구: MLE-bench에서 시도 횟수를 8번으로 늘리면 o1-preview의 메달률이 16.9% → 34.1%로 두 배가 됐고, 24시간 → 100시간으로 늘리면 GPT-4o가 8.7% → 11.8%가 됐습니다. 공식 리더보드 상위 에이전트들은 12~24시간을 씁니다.
  • 시사점: "연속 3회 미채택"보다 시간·시도 예산으로 종료하는 편이 낫습니다.
4부

연구와 실무 자료가 말하는 것

이번 판단에 꼭 필요한 것만

4.1멀티에이전트는 언제 이기고 언제 지나?

4.2실패는 어디서 오나: MAST로 본 agent-lab

MAST(NeurIPS 2025)는 7개 프레임워크의 실행 기록을 분석해 14개 실패 양식을 세 갈래로 묶었습니다. 저자들은 실패가 모델 한계만이 아니라 시스템 설계에서 오며, 겉핥기식 수정이 아닌 구조 재설계가 필요하다고 결론 냈습니다.

4.3비판·토론·자기 수정은 외부 피드백이 있을 때만 쓸모 있다

  • 외부 신호 없이 "다시 생각해 봐"는 맞던 답을 틀리게 바꾸기도 합니다(Huang 등).
  • 멀티에이전트 토론의 이득 상당 부분은 여러 번 뽑아 다수결하는 효과와 비슷합니다.
  • 실무 규칙: 비판은 반드시 실행 가능한 확인 실험과 짝짓습니다. agent-lab은 이미 이렇게 하고 있으니, 무엇을 묻는지만 넓히면 됩니다.

4.4모델을 섞으면 좋아지나: Self-MoA

  • Li 등(TMLR 2026)은 서로 다른 LLM의 출력을 섞는 MoA보다, 가장 좋은 모델 하나의 여러 출력을 모으는 Self-MoA가 많은 경우 더 낫다고 보고했습니다(AlpacaEval 2.0 +6.6%, 여러 벤치마크 평균 +3.8%).
  • 이유: 섞을수록 평균 품질이 내려가기 쉽습니다. 다양성보다 품질이 더 중요했습니다.
  • 시사점: "오픈 모델 여러 개 조합"보다 "가장 강한 오픈 모델 하나를 여러 가지·여러 번".

4.5ML 엔지니어링 에이전트 연구의 교훈

  • MLE-bench(OpenAI, ICLR 2025): 캐글 75개 대회로 에이전트를 평가합니다. 같은 모델도 스캐폴드에 따라 크게 다르고, 시도·시간을 늘리면 오릅니다.
  • AIRA-dojo(Meta 등, 2025): 탐색 정책 × 연산자. 검증 점수로 고른 최종 해와 테스트 기준 최적 해 사이에 9~13점 차이가 있어, 검증-테스트 격차가 체계적인 과적합을 낳는다고 보고했습니다.
  • MLE-STAR(Google, NeurIPS 2025): 검색으로 출발 모델, 절제 실험 기반 표적 개선, 앙상블. 누수 점검 모듈이 들어 있습니다.
  • 공식 리더보드(2026년 3월 항목까지, 4월부터 신규 접수 중단): 전체 75개 대회 메달률 최상위 64.4%(Gemini 3 Pro 기반), 63.1%(Claude Opus 4.6 기반). 상위권은 대부분 트리·그래프 탐색 기반 하네스에 12~24시간을 씁니다.

4.6정형 데이터 모델 선택: 트리가 기본이지만 늘 정답은 아니다

  • Grinsztajn 등(NeurIPS 2022): 보통의 정형 데이터에서는 트리 모델이 여전히 우세합니다. 그러나 데이터를 회전시키면(신호가 컬럼 축이 아니라 컬럼 조합 방향에 있으면) 순위가 뒤집힙니다.
  • 고장 진단 사례가 정확히 이 경우였습니다. 모델 계열 스윕이 하네스의 기본 도구여야 하는 이유입니다.

4.7검증 통계: 무엇을 더 경계해야 하나

  • Roelofs 등(2019): 캐글 대회 100여 개에서 홀드아웃 재사용으로 인한 과적합의 실질적 증거가 적었습니다. 제1저자의 학위논문은 진짜 문제는 과적합보다 분포 이동이라고 정리했습니다.
  • AIRA-dojo의 검증-테스트 격차와 함께 보면, 반복 평가 과적합보다 ① 검증셋이 test 분포를 대표하지 못하는 문제 ② 작은 개선을 버리는 2종 오류가 더 큰 손실일 때가 많습니다.
  • 실무 규칙: CV–LB(또는 CV–운영) 차이를 1순위 지표로 기록하고, 그 차이가 fold 표준편차의 몇 배인지 봅니다.
5부

멀티에이전트를 고치면 따라잡을 수 있나

역할 문구보다 구조

5.1답: 문구 수정은 조금, 구조 수정은 많이

  • 역할 설명·지침만 다듬는 것은 MAST가 말한 "겉핥기식 수정"에 가깝습니다.
  • 이번 기록에서 에이전트들은 문제를 꽤 정확히 짚었습니다(지표 불일치, 시드 잡음, 고카디널리티 교란). 막힌 곳은 판단력이 아니라 그 판단을 행동으로 바꾸는 구조였습니다.
  • 스캐폴드·환경·연산자만 바꿔 같은 모델의 성과가 크게 달라진 연구가 여럿 있습니다(4.5절, 3부 ①②).

5.2개선 로드맵 (우선순위순)

5.3제안 구조

  • 리드 과학자: 가장 강한 모델. 전체 맥락, 샌드박스 실행, 원자료 접근을 가집니다. 가설 → 실험 → 해석 사슬이 끊기지 않습니다.
  • 병렬 실험 워커: 탐색 단계에서만. 모델 계열별로 서로 독립인 가지를 돌리고 수치표를 돌려줍니다. 멀티에이전트가 실제로 유리한 "병렬화 가능한" 부분입니다.
  • 깨끗한 맥락 검토자: diff와 결과만 보고 누수·버그를 찾습니다. 리드와 맥락을 공유하지 않아 같은 착각에 빠지지 않습니다.
  • 코드 판정: 반복 CV와 잠근 홀드아웃. agent-lab의 장점을 그대로 둡니다.
  • 사람 관문: 지표, 리크 정책, 대회·업무 규칙 해석. 모델이 대신 정하면 안 되는 결정입니다.

5.4어디까지 좁혀질까? (추정)

  • 보험: 격차의 대부분인 출발점 차이는 라이브러리·설정과 실행 샌드박스로 좁혀질 가능성이 큽니다. 남는 차이는 모델 능력과 탐색 예산입니다.
  • 가치: 지표만 고쳐도 RMSLE 기준으로 의미 있게 나아질 것입니다(합성 실험의 방향). 리크 이득(1.34 → 0.50)은 정책상 대상이 아닙니다.
  • 고장 진단: 0.79 벽을 넘을 단서(QDA·LDA 효과, 적대적 검증 AUC)는 이미 로그에 있었습니다. 계열 스윕과 이상 신호 추적이 있으면 이어졌을 단서입니다.
  • 모두 확인 전 추정입니다. 7.2절 실험으로 검증하세요.
6부

내부 오픈 모델로 Opus 단독을 넘을 수 있나

숫자로 본 현재 격차

6.1범용 능력 격차: 공개 점수로 몇 개월, 비공개 과제로는 더 크다

  • Epoch AI(2026년 5월): 2026년 1월 이후 최상위 오픈 웨이트 모델은 폐쇄형 최전선보다 평균 약 4개월 뒤처졌습니다(종합 지수 ECI 약 8점, GPT-5와 GPT-5.5 차이 수준). 2025년 10월 측정(약 3개월)보다 조금 벌어졌습니다.
  • NIST CAISI(2026년 5월): 비공개 벤치마크를 포함한 평가에서 DeepSeek V4 Pro가 최전선보다 약 8개월 뒤처졌다고 봤습니다(GPT-5 수준). 비용 효율은 높았습니다. 비교 모델 선택 등 방법론에 대한 비판도 있습니다.
  • 해석: 공개 점수는 오픈 모델을 실제보다 가깝게 보이게 할 수 있습니다. 데이터 분석처럼 길고 낯선 과제일수록 격차가 커진다고 가정하는 편이 안전합니다.

6.2ML 엔지니어링 과제에서는: 하네스가 모델 차이를 뒤집기도 한다

  • 같은 오픈 모델, 다른 하네스: DeepSeek-R1이 ML-Master에서 29.3%, InternAgent에서 36.4%. 이 36.4%는 o3 기반 AIRA-dojo(31.6%)보다 높습니다. 하네스가 모델 차이를 뒤집을 수 있습니다.
  • 최상위끼리: DeepSeek-V3.2-Speciale 기반 56.4% vs Gemini 3 Pro 기반 64.4%, Claude Opus 4.6 기반 63.1%. 약 7~8점 차이입니다.
  • 같은 탐색 정책, 다른 모델: AIRA-dojo에서 R1과 o3의 전체 메달률은 비슷했고, 금메달률은 25.7% vs 30.9%였습니다.
  • 작은 특화 모델: MLExpert(Qwen3.6-35B-A3B 기반 35B MoE)는 ML 엔지니어링 특화 학습으로 MLE-bench Lite 메달률이 37.9% → 72.7%가 됐다고 보고했습니다(Claude Code 하네스로도 42.4% → 69.7%). 자체 보고이고 22개 저난도 대회 기준입니다.
주의리더보드는 2026년 4월부터 신규 접수를 중단해 최신 모델이 없습니다. 실행 시간·하드웨어가 항목마다 다르고, 캐글 공개 대회라 오염 가능성이 있습니다. 순위보다 "하네스 효과가 크다"는 방향으로 읽으세요.

6.3"조합"은 해법인가?

  • 불리한 근거: Self-MoA는 약한 모델을 섞으면 평균 품질이 내려간다고 보고했습니다. Cognition은 약한 주 모델 + 강한 조언자 패턴이 주 모델이 약하면 잘 안 된다고 했습니다(언제 물어야 할지 모름).
  • 공정하게 반대 근거도: Google 연구의 포화 효과는 뒤집어 보면 기준 성능이 낮은 모델일수록 협업 이득이 남을 수 있다는 뜻입니다. Tran & Kiela도 단일 에이전트의 맥락 활용이 약할 때 분해가 경쟁력이 있다고 했습니다.
  • 결론: 약한 로컬 모델에서는 적절한 분해가 단일 운용보다 나을 수 있습니다. 그러나 더 강한 모델 단독을 넘는다는 근거는 아닙니다.

6.4내부 운영의 현실 조건

로컬 운영의 진짜 장점은 점수보다 다음 세 가지입니다.

  1. 원자료를 줄 수 있습니다. 데이터가 밖으로 나가지 않으니 agent-lab의 가장 큰 제약(원본 행 미전달)을 풀 수 있습니다.
  2. 시도를 많이 돌릴 수 있습니다. 사용량 한도가 없어 병렬 가지·재시도를 늘릴 수 있습니다(MLE-bench의 시도 횟수 효과).
  3. 사내 과제로 추가 학습할 수 있습니다. MLExpert처럼 과제 특화 학습이 큰 폭으로 올린 사례가 있습니다.

6.5결론: 무엇과 무엇을 비교하느냐에 따라 답이 다르다

판단
내부 오픈 모델 경로를 "Opus를 이긴다"로 목표 잡으면 실망하기 쉽습니다. 같은 하네스 기준 최상위끼리는 약 9할 수준(56.4 vs 63.1)이고, 하네스가 약하면 그보다 훨씬 낮습니다. 현실적인 목표는 "데이터를 밖으로 내보내지 않고, 좋은 하네스와 사람 관문으로 그 9할에 안정적으로 닿기"입니다.

7.2결정 전에 해볼 공정한 비교 실험

  1. 목적: 모델 효과와 구조 효과를 분리합니다.
  2. 설계: 2×2 = 모델(Opus 전 역할 / 현재 혼합) × 구조(단일 리드 / agent-lab). 여기에 오픈 모델 칸(최강 오픈 모델 단일 리드)을 더합니다.
  3. 고정: 실행 권한, 라이브러리, 원자료 접근, 시간·시도 예산, 판정 지표, fold 분할.
  4. 데이터: 공개 대회가 아닌 사내 비공개 또는 최근 데이터 3개 이상(분류·회귀·불균형을 섞음). 공개 대회만 쓰면 ⑦ 때문에 결론이 기웁니다.
  5. 반복: 칸마다 시드 3회 이상.
  6. 기록: 잠근 홀드아웃 점수, 소요 시간, 토큰·비용, 사람 개입 횟수, 채택·기각 수, 재현성.
  7. 판정: 홀드아웃 평균 차이가 반복 간 표준편차의 2배 이상일 때만 "차이 있음"으로 봅니다.

7.3분석 프로세스 체크리스트 (어떤 구성이든)

시작 전

  • 공식 지표로 기준 모델 점수를 계산해 판정 지표와 같은지 확인
  • 리크 정책 명시: 행 사이 구조(중복, 시간 이동, ID 연결)를 써도 되는가
  • test 분포 점검: 적대적 검증 AUC, 예상 클래스·값 분포
  • 모델 계열 스윕: 같은 fold로 트리·선형·LDA/QDA·kNN·MLP. 계열 간 큰 차이는 구조 신호

실행 중

  • CV–LB(또는 CV–운영) 차이를 1순위로 기록
  • 이상 신호는 위험 목록이 아니라 다음 과제로
  • 반복 CV로 판정, 시간·시도 예산으로 종료

끝난 뒤

  • 잠근 홀드아웃 1회, 재현 검증, 확률 품질(log loss)도 확인

확인셀프 테스트

Q1. 보험 청구에서 Opus 최종 Gini 0.2909, agent-lab 0.2763이다. 격차의 몇 %가 출발점에서 생겼나?

(0.2825 − 0.2699) ÷ (0.2909 − 0.2763) = 0.0125 ÷ 0.0147 ≈ 85%. 출발점 차이의 정체는 라이브러리 선택과 이미 알고 있던 검증된 설정입니다.

Q2. agent-lab 가치 예측에서 log1p 학습이 기각된 진짜 이유는?

판정 지표가 원 단위 RMSE였기 때문입니다. RMSLE로 판정했다면 반대 결론이 나왔을 가능성이 큽니다(합성 실험 RMSLE 2.08 vs 1.33).

Q3. 실제 효과 +0.0009(AUC)인 개선을 현재 채택 규칙이 받아들일 확률(모의 추정)과 그 이유는?

약 30%. 시드 잡음(약 0.0007)과 fold 잡음(약 0.0008)이 문턱 0.00107과 비슷한 크기라서입니다. 3회 반복 5-fold로 잡음을 줄이고 문턱을 0.0004로 낮추면 약 86%가 됩니다. 대신 효과 0인 변경의 채택 확률이 2%에서 19%로 오릅니다.

Q4. 실무 시나리오: "오픈 모델 3개(코더·분석가·비판가)를 역할별로 섞자"는 제안이 왔다. 무엇을 먼저 확인하나?

가장 강한 오픈 모델 하나로 같은 하네스에서 단일 리드를 돌린 결과와 비교합니다. Self-MoA와 순차 과제 연구에 따르면 섞기는 평균 품질을 낮추기 쉽습니다. 그보다 먼저 실행 권한과 지표 정합을 확인합니다.

Q5. 멀티에이전트가 확실히 유리한 작업 하나와 그 이유는?

서로 독립으로 나눌 수 있는 넓은 조사(문헌·데이터 소스 탐색, 모델 계열별 독립 실험)입니다. 각 에이전트가 따로 맥락을 쓰며 토큰을 더 쓸 수 있기 때문입니다. Anthropic 리서치 +90.2%, Google 병렬 과제 +80.9%가 근거입니다.

요약핵심 세 줄

  1. 이번 격차는 '단일 vs 멀티'보다 실행 권한·원자료·라이브러리·지표·사전지식의 차이가 대부분을 만들었다.
  2. 멀티에이전트는 역할 문구가 아니라 구조(지표 정합, 샌드박스, 넓게 → 좁게 탐색, 잡음에 맞춘 채택 규칙, 단일 리드)를 고쳐야 따라붙는다.
  3. 오픈 모델은 '여럿 조합'이 아니라 '최강 하나 + 좋은 하네스 + 사람'으로 시작하고, 비공개 데이터 2×2 실험으로 결정한다.

한계이 자료를 읽을 때 주의할 점

  • 각 방식은 1회 실행입니다. 실제 리더보드 제출 점수는 제공 파일에 없었습니다.
  • Opus의 CV에는 조기 종료 낙관 편향이 있고, 최종 스크립트는 전체 데이터로 다시 돌려 보지 않았습니다(Opus 본인 기록).
  • 검정력 계산(그림 2)은 로그에서 추정한 잡음 크기에 의존합니다. 합성 실험(표 5)은 방향 확인용입니다.
  • 일부 벤치마크 수치는 개발사 자체 보고이거나 집계 사이트를 거쳐 확인했습니다(출처에 표시). MLE-bench 공식판은 2026년 3월 항목 이후 갱신이 없습니다.
