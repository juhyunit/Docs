1장

텍스트를 숫자로 바꾸기

이 장 한 문장

글자를 잘라(토큰화) 번호를 붙이고(ID), 그 번호를 뜻이 담긴 벡터로 바꾼다(임베딩). 순서 정보를 더하면 모델 입력 완성.

⏱ 10분 · 코드 PART 1 · 책 2장

1.1왜 숫자로 바꾸나

신경망은 덧셈과 곱셈만 합니다. "Hello"를 곱할 수는 없습니다. 그래서 3단계 변환이 필요합니다.

1.2단어 단위 토큰화의 한계

 사전에 있는 단어:  the, cat, house, …  (1,132개)
 입력:   "Hello, do you like tea?"
 결과:   <|unk|>, do you like tea?      ← Hello를 통째로 못 알아봄

훈련 때 못 본 단어는 전부 <|unk|>(모름)로 뭉개집니다. 사람 이름, 신조어, 오타, 외국어… 전부요.

1.3BPE — 모르는 단어를 조각내기

BPE(Byte Pair Encoding) 는 "단어를 더 작은 조각으로 쪼개기"로 해결합니다.

만드는 방법 (3줄):

  1. 글자(정확히는 바이트) 단위로 시작 → 256개
  2. 훈련 텍스트에서 가장 자주 붙어 나오는 쌍을 하나로 합침 (t+h → th)
  3. 5만 번 반복 → 흔한 단어는 통째로, 드문 단어는 조각으로 남음
 GPT-2 어휘사전 50,257 = 256(바이트) + 50,000(합친 조각) + 1(<|endoftext|>)

어떤 글자가 와도 바이트로는 쪼갤 수 있으므로 <unk>가 아예 필요 없습니다.

💡 코드에서 조각을 하나씩 출력해 보면 " do"처럼 앞 공백이 토큰에 포함됩니다. GPT-2 BPE의 특징입니다.
🔗 직접 실험: https://tiktokenizer.vercel.app 에 아무 문장이나 넣어 보세요. 한글이 얼마나 비효율적으로 잘리는지도 보입니다.

1.4특수 토큰은 하나뿐

GPT-2가 쓰는 특수 토큰은 <|endoftext|> (ID 50256) 딱 하나입니다.

  • 문서 경계 표시 — 문서1 <|endoftext|> 문서2
  • 배치 안 길이를 맞추는 패딩 (5·6장에서 등장)

1.5훈련 데이터 — 정답은 "한 칸 민 것"

LLM은 사람이 라벨을 달 필요가 없습니다. 텍스트 자체가 문제이자 정답이기 때문입니다.

 원본 토큰:  [ I ]  [ HAD ]  [ always ]  [ thought ]  [ Jack ]

 입력 x :    [  I  ,  HAD  ,  always  ,  thought  ]
                  ↘      ↘        ↘          ↘        ← 한 칸씩 밀림
 타깃 y :         [ HAD  , always ,  thought ,  Jack  ]

여기서 중요한 사실. 길이 4짜리 시퀀스 하나가 4개의 문제를 담고 있습니다.

본 것 맞혀야 할 것
I HAD
I HAD always
I HAD always thought
I HAD always thought Jack

2장의 코잘 마스크 덕분에 이 4문제를 한 번의 계산으로 전부 풉니다. 트랜스포머 훈련이 빠른 핵심 이유입니다.

stride는 윈도를 몇 칸씩 밀지 정합니다. stride = max_length면 겹치지 않게 자릅니다(책의 훈련 설정).

1.6임베딩 = 학습되는 룩업 테이블

nn.Embedding(50257, 768)은 어렵게 생겼지만 그냥 50,257행 × 768열짜리 표입니다.

  • 처음엔 랜덤 숫자입니다.
  • 훈련하면서 비슷한 뜻의 단어가 비슷한 벡터가 되도록 스스로 배웁니다.

🔍 손으로 확인 — 벡터가 "뜻"을 담는다는 게 무슨 말인가?

 king = [ 0.9, 0.1]     queen = [ 0.8, 0.2]     banana = [-0.7, 0.6]

 king · queen  = 0.9×0.8 + 0.1×0.2  =  0.74   ← 크다 = 비슷하다
 king · banana = 0.9×(-0.7) + 0.1×0.6 = -0.57  ← 작다 = 안 비슷하다

점곱(내적)이 클수록 비슷하다. 이 사실 하나가 2장 어텐션의 출발점입니다.

💡 임베딩은 원-핫 벡터에 행렬을 곱한 것과 수학적으로 같습니다. 다만 "행 하나 꺼내기"가 훨씬 빠릅니다.

1.7위치 임베딩 — 순서를 알려 주기

곧 배울 어텐션은 순서를 모릅니다. "개가 사람을 물었다"와 "사람이 개를 물었다"를 같은 단어 자루로 봅니다. 그래서 "너는 3번째야"라는 정보를 벡터로 더해 줍니다.

   입력 벡터  =  토큰 임베딩(무슨 단어)  +  위치 임베딩(몇 번째)

    " world"의 뜻        3번째 자리
   [0.77, -0.11, …]  +  [0.05, 0.30, …]  =  [0.82, 0.19, …]

GPT-2는 위치마다 벡터를 하나씩 학습합니다(nn.Embedding(1024, 768)). 그래서 문맥 길이가 1024로 고정됩니다. 최신 모델은 RoPE(회전 방식)를 쓰지만 "순서를 벡터에 새긴다"는 목적은 같습니다.

✅ 1장 정리 ─────────────────────────────────────────────────┐

  1. 텍스트 → BPE 토큰 ID → 임베딩 벡터 + 위치 벡터 = 모델 입력
  2. 정답은 입력을 한 칸 민 것. 사람의 라벨링이 필요 없다.
  3. 임베딩은 훈련되는 룩업 표. 점곱이 크면 비슷한 뜻.
2장

어텐션 — LLM의 심장 ⭐

이 장 한 문장

각 토큰이 다른 토큰들을 "얼마나 참고할지" 비율로 정하고, 그 비율대로 정보를 섞어 문맥이 반영된 새 벡터를 만든다.

⏱ 25분 · 코드 PART 2 · 책 3장 ← 시간을 가장 많이 쓸 곳

2.1왜 필요한가 — bank 문제

  "river bank"    →  bank = 강둑
  "bank account"  →  bank = 은행

1장의 임베딩은 "bank"에 항상 같은 벡터를 줍니다. 뜻이 문맥에 따라 달라지는데도 말이죠. 그래서 주변을 보고 벡터를 고쳐 쓰는 장치가 필요합니다.

회의 비유: 각자 자기 의견(임베딩 벡터)을 들고 회의실에 들어갑니다. 회의(어텐션)에서 남의 말을 듣되, 관련 있는 사람 말은 많이 듣고 관련 없는 사람 말은 흘립니다. 회의가 끝나면 각자의 의견이 업데이트됩니다(문맥 벡터).

2.2어텐션 3단계 — 손으로 직접 계산하기 🔍

토큰 3개, 각 벡터가 2차원인 아주 작은 예로 전 과정을 계산해 봅시다.

   A = [1, 0]      B = [0, 1]      C = [1, 1]

① 점수(score): 점곱으로 관련도 재기

C가 다른 토큰들과 얼마나 관련 있나?

  C·A = 1×1 + 1×0 = 1
  C·B = 1×0 + 1×1 = 1
  C·C = 1×1 + 1×1 = 2      ← 자기 자신과 가장 비슷 (당연)

  점수 = [1, 1, 2]

② 가중치(weight): softmax로 비율 만들기

softmax는 "각 값에 e를 씌우고, 전체 합으로 나눈다"가 전부입니다.

  e¹ = 2.718    e¹ = 2.718    e² = 7.389        합 = 12.826

  2.718 / 12.826 = 0.212
  2.718 / 12.826 = 0.212
  7.389 / 12.826 = 0.576                   합 = 1.000 ✓

  가중치 = [0.212, 0.212, 0.576]

③ 문맥 벡터: 가중합

  z(C) = 0.212×[1,0] + 0.212×[0,1] + 0.576×[1,1]
       = [0.212, 0] + [0, 0.212] + [0.576, 0.576]
       = [0.788, 0.788]

끝입니다. 어텐션은 이 3단계가 전부입니다. 차원이 768로 커지고 토큰이 1024개로 늘어날 뿐, 계산은 똑같습니다.

왜 하필 softmax인가? 세 가지를 한 번에 해 주기 때문입니다.

  • 음수를 없앤다 (e를 씌우면 전부 양수)
  • 합을 1로 만든다 → "비율"로 해석 가능
  • 큰 값은 더 키우고 작은 값은 더 줄인다 → 중요한 것에 집중

전체 문장에 대해 한꺼번에 하면 행렬 곱 두 번입니다.

python
weights = softmax(X @ X.T)   # (6,3)@(3,6) = (6,6)  모든 쌍의 관계
context = weights @ X        # (6,6)@(6,3) = (6,3)  모든 토큰의 새 벡터

2.3문제점: 배우는 게 없다

2.2의 어텐션에는 학습되는 파라미터가 하나도 없습니다. 입력끼리 점곱할 뿐이라, 모델이 "무엇에 주목할지"를 조정할 수 없습니다. 그래서 학습 가능한 행렬 3개를 끼워 넣습니다.

2.4Q · K · V — 도서관 비유

역할 도서관 비유 예
Query 내가 검색창에 치는 말 "고양이 키우기"
Key 책 등에 붙은 라벨 "반려동물" / "요리" / "물리"
Value 책의 실제 내용 본문

검색어(Q)와 라벨(K)을 비교해서, 관련도가 높은 책의 내용(V) 을 더 많이 가져옵니다.

  scores  = Q @ Kᵀ                     ← 질문 vs 이름표
  weights = softmax(scores / √d_k)     ← 비율로
  context = weights @ V                ← 내용물을 비율대로 섞기

왜 굳이 셋으로 나누나? "내가 남에게 던지는 질문"과 "내가 남에게 보여 주는 이름표"는 달라야 하기 때문입니다.

예: 대명사 "it"은 "앞에 나온 명사를 찾는다"고 묻지만(Q), 다른 단어들이 "it"을 찾아올 이유는 별로 없습니다(K). 벡터 하나로는 이 비대칭을 표현할 수 없습니다.

왜 √d_k로 나누나?

  차원 768  →  숫자 768개를 곱해 더함  →  점수가 커짐
  점수가 크면 softmax가 한 곳에만 1.0을 몰아줌 (뾰족)
  → 나머지가 전부 0 → 학습 신호(기울기)가 사라짐

  √d_k로 나누면 차원과 무관하게 점수 크기가 일정해짐 ✓

그래서 이 방식의 이름이 스케일드 점곱 어텐션(scaled dot-product attention) 입니다.

2.5코잘 마스크 — 미래를 가려라

목표는 다음 토큰 예측입니다. 그런데 어텐션이 문장 전체를 보면, "journey" 다음을 맞힐 때 이미 "starts"를 훔쳐봅니다. 시험 중 답안지를 보는 셈입니다.

🔍 손으로 확인 (2.2의 A, B, C 예제 계속)

마스크 없는 점수 행렬:

         A   B   C
    A [  1   0   1  ]
    B [  0   1   1  ]
    C [  1   1   2  ]

미래 자리를 −∞ 로 덮기 (대각선 위쪽):

         A     B     C
    A [  1   -inf  -inf ]
    B [  0     1   -inf ]
    C [  1     1     2  ]

softmax를 걸면 (e^−∞ = 0):

         A      B      C
    A [ 1.000  0.000  0.000 ]   ← A는 자기만 봄
    B [ 0.269  0.731  0.000 ]   ← B는 A와 자기만 봄
    C [ 0.212  0.212  0.576 ]   ← C는 전부 봄
              각 행의 합은 여전히 1 ✓

B행 계산: softmax([0, 1]) = [e⁰, e¹] / (e⁰+e¹) = [1, 2.718] / 3.718 = [0.269, 0.731]

왜 0이 아니라 −∞?

방법 결과
softmax 후에 0을 곱함 행의 합이 1이 아니게 됨 → 다시 정규화해야 함 (번거로움)
softmax 전에 −∞ e^−∞ = 0이라 자동 제외되고 나머지 합이 정확히 1 ✓
python
mask = torch.triu(torch.ones(T, T), diagonal=1)   # 대각선 위쪽만 1
scores.masked_fill_(mask.bool(), -torch.inf)

💡 이 마스크 덕분에 1.5의 "길이 T 시퀀스 = T개의 문제"가 성립합니다. 위치 3의 출력은 토큰 1~3만 본 결과이므로 "토큰 4 맞히기"의 답으로 쓸 수 있습니다.

2.6드롭아웃 — 한 곳에 의존하지 않기

훈련 중에 어텐션 가중치의 일부(예: 10%)를 무작위로 0으로 만듭니다. 특정 연결에만 의존하지 못하게 해 과대적합을 막습니다. 살아남은 값은 1/(1−p)배로 키워 평균을 유지합니다. 추론 시(model.eval())에는 꺼집니다.

2.7멀티헤드 — 여러 관점으로 동시에

어텐션 하나는 한 종류의 관계만 잡습니다. 문장에는 여러 관계가 있습니다(주어-동사, 대명사-선행사, 형용사-명사…). 그래서 어텐션을 여러 개 병렬로 돌립니다. 각각이 헤드(head) 입니다.

각 헤드가 자기만의 Q/K/V와 자기만의 T×T 가중치 표를 갖습니다.

모양 추적표 — 코드 MultiHeadAttention.forward와 한 줄씩 대응합니다.

코드 모양 무슨 일
입력 x (b, T, 768) 시작
W_q(x) (b, T, 768) Q 만들기
.view(b,T,12,64) (b, T, 12, 64) 768 = 12헤드 × 64로 쪼갬
.transpose(1,2) (b, 12, T, 64) 헤드를 앞으로 (배치처럼 취급)
q @ k.transpose(2,3) (b, 12, T, T) 헤드마다 토큰×토큰 점수
마스크 + softmax (b, 12, T, T) 가중치
@ v (b, 12, T, 64) 헤드별 문맥 벡터
.transpose(1,2).reshape (b, T, 768) 헤드 이어 붙이기
out_proj (b, T, 768) 헤드들을 한 번 더 섞음

⚠️ 자주 하는 오해: 헤드가 12개면 계산량도 12배? 아닙니다. 768차원을 쪼개 쓰므로 총 계산량은 거의 같습니다. 공짜로 관점만 늘리는 셈입니다.

2.8이 공식 하나는 외우세요

                          ┌─ 마스크: 미래는 −∞
                          │
   Attention(Q,K,V) = softmax( Q·Kᵀ / √d_k ) · V
                                │      │        │
              누가 누구와 관련? ─┘      │        └─ 비율대로 정보 섞기
                        크기 안정화 ────┘

✅ 2장 정리 ─────────────────────────────────────────────────┐

  1. 어텐션 = 점수(점곱) → 비율(softmax) → 가중합. 3단계 끝.
  2. Q/K/V는 학습되는 행렬로 만든 질문·이름표·내용물.
  3. 코잘 마스크(−∞)로 미래를 가리고, 멀티헤드로 여러 관점.

GPT 조립하기

이 장 한 문장

[어텐션 + FFN] 한 세트를 블록으로 만들고, 잔차 연결과 LayerNorm을 붙여 12번 쌓으면 GPT가 된다.

⏱ 15분 · 코드 PART 3 · 책 4장

3.1전체 구조도

핵심 리듬: 어텐션 = 정보를 주고받기(communicate), FFN = 받은 정보를 혼자 가공하기(compute). 이 둘을 12번 반복하면 얕은 문법에서 깊은 의미까지 층층이 쌓입니다.

3.2부품 4개

① LayerNorm — 값의 크기 맞추기

깊은 신경망은 층을 지날수록 값이 폭주하거나 소멸합니다. LayerNorm은 각 토큰 벡터를 평균 0, 분산 1로 맞춥니다.

🔍 손으로 확인

  벡터 [2, 4, 6]
   평균 = 4,  분산 = ((2−4)² + (4−4)² + (6−4)²)/3 = 8/3 = 2.67,  표준편차 = 1.63

  (2−4)/1.63 = −1.22
  (4−4)/1.63 =  0.00      →  [−1.22, 0, 1.22]   평균 0, 분산 1 ✓
  (6−4)/1.63 =  1.22

  마지막에:  scale × 결과 + shift    ← 학습 가능 (표현력 회복)
  • dim=-1, 즉 특성 방향으로 계산합니다. 토큰마다, 샘플마다 독립적입니다.
  • eps(1e-5)는 분산이 0일 때 0으로 나누는 것을 막습니다.
  • GPT-2는 Pre-LN(부품 앞에 정규화)입니다. 원조 트랜스포머(2017)의 Post-LN보다 훈련이 안정적이라 지금은 이게 표준입니다.

② GELU — 부드러운 활성화 함수

활성화 함수는 비선형성을 넣어 복잡한 함수를 배울 수 있게 합니다.

식은 외울 필요 없습니다. "ReLU의 부드러운 버전" 이면 충분합니다.

③ FeedForward — 넓혔다 좁히기

  • 토큰 하나씩 독립적으로 통과합니다. 토큰 간 교류는 없습니다(그건 어텐션 몫).
  • 넓혔다 좁히는 이유: 넓은 공간에서 풍부한 패턴을 찾은 뒤 압축.
  • 최근 연구는 FFN을 사실·지식이 저장되는 창고로 봅니다. 블록 파라미터의 약 2/3가 여기 있습니다.

④ 잔차(숏컷) 연결 — 기울기 고속도로

x = x + f(x). 부품의 출력에 입력을 그대로 더합니다.

책의 실험(ExampleDeepNeuralNetwork) 결과: 숏컷이 없으면 첫 층 기울기가 0.0002, 있으면 0.2. 1000배 차이입니다.

효과가 둘입니다.

  • 각 층은 "처음부터 만들기"가 아니라 "조금 고치기" 만 배우면 됩니다.
  • 역전파 신호가 소멸하지 않습니다.

수백 층짜리 최신 모델이 훈련되는 건 전적으로 이 한 줄 덕분입니다.

3.3파라미터 1.24억 개는 어디에 있나

GPT-2 small 기준 (768차원, 12층, 12헤드):

부품 계산 개수
토큰 임베딩 50257 × 768 38.6M
위치 임베딩 1024 × 768 0.8M
블록 1개 · 어텐션 4 × 768² + 편향 2.4M
블록 1개 · FFN 2 × 768×3072 + 편향 4.7M
블록 12개 7.1M × 12 85.1M
출력층 50257 × 768 38.6M

3.4텍스트 생성 — 한 토큰씩, 반복

  • 매번 전체 시퀀스를 다시 넣습니다(단순 구현). 실제 서비스는 KV 캐시로 이전 계산을 재활용합니다.
  • 문맥 길이를 넘으면 앞을 잘라냅니다: idx[:, -context_size:]
  • 훈련 전 모델은 가중치가 랜덤이라 완전한 헛소리를 뱉습니다. 이제 가르칠 차례입니다.

✅ 3장 정리 ─────────────────────────────────────────────────┐

  1. GPT = 임베딩 → [LN→어텐션→+][LN→FFN→+] × N → LN → 출력층
  2. 어텐션은 토큰 간 소통, FFN은 토큰별 계산·지식 저장.
  3. 잔차 연결이 깊은 신경망 훈련을 가능하게 하는 핵심 트릭.

사전 훈련

이 장 한 문장

"정답 토큰에 얼마나 높은 확률을 줬나"를 손실로 삼아, 그 손실이 줄어드는 방향으로 파라미터를 조금씩 고친다.

⏱ 15분 · 코드 PART 4 · 책 5장

4.1손실 = 정답 확률의 −log

모델이 정답 토큰 " you"에 확률 0.61을 줬으면 잘한 것, 0.001을 줬으면 못한 것입니다. 이걸 숫자 하나로 만든 것이 크로스 엔트로피입니다.

   손실 = −log( 정답 토큰에 준 확률 )  의 모든 위치 평균

🔍 표로 감 잡기

정답에 준 확률 −log(확률) = 손실 상태
1.00 0.00 완벽
0.90 0.11 아주 좋음
0.50 0.69 반반
0.10 2.30 나쁨
0.01 4.61 엉망
1/50257 (찍기) 10.82 훈련 전

혼잡도(perplexity) = e^손실 — "모델이 몇 개 후보 사이에서 헷갈리나"로 읽으면 됩니다.

   손실 10.8  →  ppl ≈ 50,000     5만 개 중 아무거나 찍는 수준 (훈련 전)
   손실  2.3  →  ppl ≈ 10         10개 중 헷갈림
   손실  0.7  →  ppl ≈ 2          2개 중 헷갈림 (아주 좋음)

💡 코드 PART 4(a)에서 정답 확률을 직접 뽑아 −log 평균을 낸 값과 F.cross_entropy 결과가 소수점까지 똑같이 나옵니다. 크로스 엔트로피는 마법이 아니라 그냥 이 계산입니다. 꼭 눈으로 확인하세요.

4.2훈련 루프 — 네 줄이 전부

python

    optimizer.zero_grad()        # ① 이전 기울기 지우기
    loss = loss_fn(x, y, model)  # ② 정방향 계산 + 손실
    loss.backward()              # ③ 역전파: 각 파라미터의 책임 계산

훈련 손실만 떨어지고 검증 손실이 멈추면 외우기 시작한 것(과대적합)입니다.

4.4디코딩 전략 — 어떤 토큰을 고를까

🔍 실제 숫자로 (책 5.3.1의 로짓, 상위 몇 개만 표시)

forward toward closer pizza 느낌

model.state_dict()는 "층 이름 → 가중치 텐서" 사전일 뿐입니다.

여기서 놀라운 사실: 우리가 만든 GPTModel은 OpenAI GPT-2와 구조가 100% 같습니다. 그러니 OpenAI가 거대 데이터로 훈련한 가중치를 그대로 끼워 넣을 수 있습니다.

   OpenAI 이름               우리 이름
   ───────────────────────────────────────────────────────────────
   wte.weight         →      tok_emb.weight
   wpe.weight         →      pos_emb.weight
   h.0.attn.c_attn    →      trf_blocks[0].att.W_query/W_key/W_value  (하나를 셋으로)
   h.0.mlp.c_fc       →      trf_blocks[0].ff.layers[0]
   ln_f               →      final_norm
   wte.weight (재사용) →     out_head.weight     ← 가중치 공유
  • 저장된 행렬이 (입력, 출력) 모양이라 nn.Linear의 (출력, 입력)에 맞춰 .T(전치) 합니다.
  • GPT-2는 Q/K/V에 편향을 쓰므로 qkv_bias=True 여야 모양이 맞습니다.

RUN["PART4_load_gpt2"] = True로 켜 보세요. 이 순간, 여러분이 짠 코드가 진짜 GPT-2가 됩니다.

✅ 4장 정리 ─────────────────────────────────────────────────┐

  1. 손실 = −log(정답 확률)의 평균. 혼잡도 = e^손실.
  2. 훈련 = zero_grad → loss → backward → step 의 반복.
  3. 온도·top-k로 다양성 조절. 구조가 같으면 남의 가중치도 OK.

6.1문제: 기초 모델은 "이어 쓰기"만 한다

6.2데이터 형식 (Alpaca 스타일)

(지시, 입력, 답변) 1,100개를 아래 틀에 넣어 하나의 긴 텍스트로 만듭니다.

   Below is an instruction that describes a task. Write a response that
   appropriately completes the request.

   ### Instruction:
   Rewrite the sentence using a simile.

   ### Input:
   The car is very fast.

   ### Response:
   The car is as fast as lightning.<|endoftext|>

6.3⭐ 핵심: 훈련은 사전 훈련과 완전히 같다

   사전 훈련 :  소설 텍스트        →  다음 토큰 맞히기  (loss_next_token)
   지시 튜닝 :  위 형식의 텍스트   →  다음 토큰 맞히기  (loss_next_token)
                      ↑                          ↑
                  데이터만 다름             함수는 똑같음!

모델은 "### Response: 뒤에는 답이 온다" 는 패턴을 다음 토큰 예측만으로 배웁니다. ChatGPT류도 원리는 같습니다(뒤에 선호도 학습이 더 붙을 뿐).

8.2헷갈리는 것 FAQ

Q. 어텐션 "점수"와 "가중치"의 차이는?
점수(score)는 softmax 전의 날것(점곱 값, 범위 제한 없음). 가중치(weight)는 softmax 후(0~1, 행의 합 1). 마스크는 점수에, 드롭아웃은 가중치에 겁니다.

Q. 로짓과 확률의 차이는?
로짓은 출력층이 뱉는 날 점수(음수 가능). softmax를 거쳐야 확률(합 1)이 됩니다. argmax는 둘 중 어디에 해도 결과가 같습니다. 단, cross_entropy는 내부에서 softmax를 하므로 반드시 로짓을 넣어야 합니다.

Q. 마스크에 0이 아니라 −∞를 쓰는 이유는?
0을 넣으면 e⁰ = 1이라 "약간 참고"하는 셈이 됩니다. −∞여야 e^−∞ = 0으로 완전히 제외되고 나머지 합이 정확히 1이 됩니다.

Q. 왜 √d_k로 나누나?
차원이 클수록 점곱이 커져 softmax가 한 곳에 몰리고 기울기가 죽습니다. 크기를 차원과 무관하게 맞추는 것입니다.

Q. 타깃을 왜 한 칸 미나?
위치 i의 출력은 "토큰 i+1이 무엇인가"의 예측이기 때문입니다. 코잘 마스크로 위치 i가 i+1을 못 보게 했으니 정답으로 쓸 수 있습니다.

Q. 임베딩은 원-핫과 뭐가 다른가?
같습니다. 원-핫 × 행렬 = 행렬의 한 행. 임베딩 층은 그 행을 바로 꺼내는 빠른 구현일 뿐입니다.

Q. model.train()과 model.eval()은?
드롭아웃을 켜고(train) 끄는(eval) 스위치입니다. 평가·생성 때 eval을 안 하면 결과가 매번 달라집니다. torch.no_grad()는 별개로, 기울기 계산을 꺼서 메모리·속도를 아끼는 것입니다.

Q. 파라미터 vs 하이퍼파라미터?
파라미터는 훈련으로 배우는 숫자(1.24억 개). 하이퍼파라미터는 사람이 정하는 설정(층 수, 차원, 학습률, 배치 크기…).

Q. 문맥 길이를 늘리면 왜 그렇게 비싼가?
어텐션 점수 표가 T×T이기 때문입니다. 토큰 수의 제곱으로 늘어납니다.

   T =   128  →       16,384칸
   T = 1,024  →    1,048,576칸      (64배)
   T = 8,192  →   67,108,864칸      (4,096배)

Q. 분류에서 왜 마지막 토큰만?
코잘 어텐션에서 마지막 토큰만이 문장 전체를 본 유일한 자리이기 때문입니다.

Q. 지시 튜닝인데 왜 손실 함수가 사전 훈련과 같나?
"답변 형식의 텍스트를 이어 쓰기"도 결국 다음 토큰 예측이기 때문입니다. LLM에게 가르치는 모든 것은 결국 "이 문맥 다음엔 이 토큰"입니다.

마지막 한 문장

LLM은 "다음 토큰 맞히기"라는 단순한 목표를, 어텐션(정보 교환)과 잔차 연결(깊이 확보)이라는 두 장치로 대규모 데이터에 적용한 것이다.

이 문장을 자기 말로 다시 설명할 수 있다면, 핵심은 당신 것입니다.
